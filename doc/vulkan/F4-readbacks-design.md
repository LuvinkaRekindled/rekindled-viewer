# F4: readbacks, snapshots, media textures (design and status, 2026-10-20)

Part of `F3-plan.md` / `PLAN-gpu-scene.md` (Foundation F). Measured before F4 started (after F3.6g, `57eda146`): the producer API for readbacks and uploads is already typed (`LLVkTex::getImage / readPixels / copySubImage`, `LLVkTarget::readPixels`, F1.6 + F3.6e/f), queries / fences are done (F1.6), the worker handlers are typed (`LLVkGL::tex_*`, `read_pixels`). What is still GL-shaped in this family is **state that lives beside the calls** and **numbers on external protocols**:

| What | Where | Verdict |
|---|---|---|
| **Pixel store state** (`glPixelStorei` shape): a thread-local unpack alignment (default 4, set to 1 only on the main thread), unpack row length (set around one call), a pixel unpack buffer id (never set by anyone), `sCtx.mPixelPackBuffer` (never set) | `llvkasync.cpp`, `llvkgl.cpp`, `llvktex.h` | **F4.1 (done)**: values of the call |
| `mFormatSwapBytes` / `swap_bytes` (`GL_UNPACK_SWAP_BYTES`): stored, never read | `LLImageGL`, `LLGLTexture`, `LLViewerDynamicTexture`, media | **F4.1 (done)**: deleted |
| `LLRenderTarget::sCurFBO` as "the source of a copy or read" (`copySubImage / copyImage2D / readPixels` take the id of the current target; 0 = back buffer) | `llimagegl.cpp` (2), `llpostprocess.cpp`, `llrender.cpp` (`readPixels`), the probe copies | F4.2: name the source as a value of the caller (the target it just rendered to), keep `sCurFBO` inside `LLRenderTarget` only |
| Media plugin protocol: GL numbers on the wire (`format`, `type`, `internalformat`, `swap_bytes` messages of `media_plugins/*`) | `llpluginclassmedia`, `media_plugin_cef/libvlc/gstreamer` | **kept**: the plugins are separate processes and an external protocol; decoded in one place (`texelFormatFromGL / pixelFormatFromGL / componentTypeFromGL`, `llviewermedia.cpp`). ## F4.1 pixel store as values (2026-10-20)
`LLVkTex::PixelStore` is `{ mAlignment = 1, mRowLength }`: **rows of client pixels are tightly packed** (alignment 1) and a sub rectangle names its row length as an argument (`LLVkTex::subImage2D(..., pixels, row_length)`; `LLImageGL::setSubImage` passes `data_width`). Deleted: `setUnpackAlignment / setUnpackRowLength` and their thread-local shadow (`tlsPixelStore`), `inline_pixel_store()`, the pixel unpack buffer path (upload mode 2, `pixel_source`, `edit_unpack_buffer`, `sCtx.mPixelUnpackBuffer`), the pixel pack buffer path (`pack_destination`, `sCtx.mPixelPackBuffer`), `TexArgs::mAlignment / mUnpackBuffer`, `mFormatSwapBytes` and the `swap_bytes` arguments of `setExplicitFormat / generateGLTexture`. **Behaviour change (a fix by reading):** a thread other than the main thread used the default alignment 4 (only `LLRender::init` set 1, on the main thread), so an upload of tightly packed RGB / R data whose row is not a multiple of 4 bytes from another producer thread would have been read with padded rows; every thread now reads tightly packed rows (what the viewer's data is). Note: the record `TexArgs` is 8 bytes smaller.
Beach run `f4a2-beach` (build of F4.1) against the F3.6f baseline set: the `FormatVerify` lines (formats, call sites, targets, settings, swizzles, level queries) are the same set; bindTarget 37.2, clear 16.1, worker passes 54.1, 0 PassCheck / StateGuard / MatrixGuard warnings, no `unknown command`, same warning categories (avatar `wt 0`, HTTP, texture fetch, `VkRt buildScene` 39-40 as in every run since F3.6d). Picture judged by eye: `f4a2-beach-b.png` (terrain, water, sky, palms, avatar, chat, toolbar, the minimap with its object dots: complete; the minimap is zoomed out compared with earlier runs: `MiniMapScale` is a saved user setting that Adam's interactive login between the runs can have changed, not verified). Not run: sub-rectangle uploads other than the minimap / font bitmap cases, media textures, snapshots, texlayer bakes (Adam's hand test).

## F4.2 copy and read sources as values (2026-10-20)
`LLRender::copyTexSubImage2D / 3D` take a `const LLRenderTarget* source` (null: the back buffer) instead of the raw id `LLRenderTarget::sCurFBO`; the producer's id comes from `LLRenderTarget::idOf(source)`. The three internal copies (`LLImageGL::setSubImageFromFrameBuffer`, `scaleDown`, `LLPostProcess::copyFrameBuffer`) and `LLRender::readPixels` read "the target of the innermost open pass" through `LLRenderTarget::currentId()` (derived from the stack of open passes; it still returns `sCurFBO`, the parallel cache, and `LL_VK_PASS_CHECK` warns when the two disagree). The probe copies (`LLHeroProbeManager`, `LLReflectionMapManager`: 5 sites) pass `LLRenderTarget::getCurrentBoundTarget()`, the scene monitor passes `nullptr` (the main frame buffer, as before). `LL_VK_PASS_CHECK` also checks every named copy source against the current frame buffer (`LLRenderTarget::checkSource`). `sCurFBO` is no longer read outside `llrendertarget.cpp` (it stays as the current-target cache of the pass machinery, see F3.5d). Beach run `f4b2-beach` (with the checks): the `FormatVerify` set is the F3.6f baseline set (it contains the cube array copy `copySubImage 2 -1` of the probes), 0 `PassCheck` warnings (no copy named a source that was not the current frame buffer), bindTarget 37.1, clear 16.0, worker passes 54.3, 0 StateGuard / MatrixGuard warnings, no `unknown command`; pictures judged by eye: `f4b1-beach-b.png` and `f4b2-beach-b.png` (terrain, water, sky, avatar, minimap with its object dots, chat, toolbar: complete; the white splash particle at the pier as in earlier runs). Not run: `readPixels` (snapshots, texlayer bake), `scaleDown`, `copyFrameBuffer`, `setSubImageFromFrameBuffer` (dynamic textures, terrain paint): Adam's hand test.
Decision: the readPixels callers of the snapshot / colour pick / fast timer code read the bound target by design (the screen, or the snapshot scratch target); they keep the implicit form, documented in `llrender.h`.
