## Candidates, in the order I would take them
1. **Cleanups that are safe and make later work cheaper** (no behaviour change, small): there are **81 `LL_VK_*` environment switches** in the code, many from the GL-era design (`LL_VK_MIRROR_GLONLY`, `MIRROR_DROP`, `MIRROR_BENCH`, `OWN`, `TYPED`, `EMBED`, `DRAW_SERIAL*`, `UNIFORMREC=0/1` per-uniform records, `STATE_WHY`, `TEXUNIT_VERIFY` ...): each one is a path that has to be kept working. Walk them (read, delete the obsolete ones, keep the diagnostics that name an open question), delete `LL_VK_UNIFORMREC` modes 0 / 1 and the producer / worker code of the per-uniform records. Update `REGRESSION-CHECKLIST.md`, `PLAN-gpu-scene.md` (stages F0-F5 are done: mark them), `F3-plan.md` status, and add the F4 hand-test list to the checklist.
2. **Worker per draw cost and uniform application** (the limit at the beach and in crowds): measure first with the counters that exist (`RT_OPSTATS=1`, `RT_NO_PHASES=1`: worker draw ns per record, apply uniforms ms per frame, passes) at the beach AND in a crowd (London); the earlier numbers (about 1.0 us per draw, 3.5 ms apply uniforms at F2.4) are from before the uniform classes (F2.3 / F2.5). Candidates there: executor caches (F2.7b: program / vertex binding / sampler slot per record), pass / material uniform blocks as in `PLAN-gpu-scene.md` (13.5k `uniform*` calls per frame is still a lot for what are a few hundred distinct values per pass).
3. **Pass structure** (F3.5 leftovers): delete the worker's per-draw depth read-only inference (needs the `DepthRO` MISSING count 0 in plaza / probes / impostors / HUD / water / snapshots: Adam's hand tests with `LL_VK_DEPTHRO_VERIFY=1`), the worker's lazy pass begin (`mPendingClear`, `mBeginSplit`), the 143 layout transitions per frame (scene colour f97 sample / attach 30, main depth 21, depth copy 15-19, reflection mip 19): the frame graph question (N2).
4. **Deferred from F3.4:** untextured immediate batches take white from their own record (needs homogeneous batches: today `unbind` flushes the batch and is the boundary).
5. **Open items from the memory notes**: the cumulative CPU cost of going to a new sim (London -> beach: 80% GPU CPU-bound until relog; reproduce by teleporting, not by a scripted login), ray shadows leaf pop-in and the material table (`project-rt-materials`), per-object motion vectors for flexi tips / eyeballs, DLSS ray reconstruction (handoff doc `HANDOFF-2026-10-14-ray-reconstruction.md`), BC7 textures, startup time, stalls.
6. **Updates the foundation work makes possible** (small and local, mentioned so they are not forgotten): the unit tests in `indra/newview/tests` and `llrender/tests` were adjusted by name only and are not built here; the SDL / macOS / Mesa window code still includes GL headers that no longer exist (not built on Windows); `RKVkBridge` (the old "mirror") is a facade whose name and comments still describe the GL design (rename of the comments, not of behaviour).

## Cleanup of the LL_VK_* switches (candidate 1), 2026-10-20: what was walked and what went
Read the 81 switches (`getenv("LL_VK_...")` in `indra/`). **The viewer always sets `LL_VK_MIRROR`, `LL_VK_OWN`, `LL_VK_EMBED=main` and `LL_VK_ASYNC=1` at start** (`llappviewer.cpp`), so the code for "mirror off / not owning / separate window / OpenGL carries on" was dead since there is no OpenGL.
**Deleted:** `LL_VK_MIRROR_BENCH` / `MIRROR_GLONLY` (the GL-vs-Vulkan timing benchmark and its hooks in the worker), `MIRROR_DROP` (frames are never dropped), `EMBED` (the separate and the child mirror window: Vulkan presents into the main window), `OWN` (`gOwn`, always on), `NUDGE`, `SIZELOG`, `LL_VK_MIRROR` as a request (`isRequested`: always; the variable is kept only as the app's "configured by hand, do not translate the settings" marker), `LL_VK_UNIFORMREC` (modes 0 / 1: the per-uniform value cache and the verify copy `mShadowNew`, `writeRangeVerify`, `uniform_check`, `draw_check_report`; the main producer always sends range writes, other producers keep per-uniform records), `LL_VK_TYPED`, `LL_VK_FULL_MIPS`, `LL_VK_RT_NAMELEAK` (A/B switches to behaviour that no longer exists), the Phase 1 bring-up probe window (`rkvkprobe.*`, 543 lines, the `FSVulkanProbe` setting and its call in `display()`). `rkvkbridge.cpp` 1360 -> 844 lines; in all 14 files, 760 lines gone. CMake needed `cmake-regen.bat` for the probe.
**Kept on purpose (diagnostics or tuning, each names an open question or is used by the launchers / run scripts):** `OPSTATS`, `PHASES`, `WORKERPHASES`, `STATS`, `VALIDATION`, `DEBUG_SHADERS`, `SHADER_CHECK`, `SHADER_DUMP_DIR`, `PROGRAM_MAP`, `FORMAT_VERIFY`, `DEPTHRO_VERIFY`, `PASS_CHECK`, `STATE_GUARD_CHECK`, `MATRIX_GUARD_CHECK`, `STATE_WHY`, `TEXUNIT_VERIFY`, `DLSS`, the `RT_*` experiments, `PRESENT`, `SC_IMAGES`, `PIPELINE_*`, `SPIRV_CACHE`, `ASYNC` (+`ASYNC_DEPTH`: `LL_VK_ASYNC=0` is the inline mode the viewer also runs in before the queue starts), `READBACK_*`, `BUILDER_THREADS`, `BUILDER_VERIFY`, `EARLY_SORT`, `UI_SUBSTREAM`, `SUBSTREAM_TEST`, `BINDLESS` (the classic path fallback), `ARENA*`, `DEVICE_BUF_MIN`, `NO_DEVICE_BUFFERS`, `NO_QUERIES`, `DRAW_*` / `ADDR_LOG` / `COARSE_BARRIERS` / `NO_END_FLUSH` / `RING_*` / `SCISSOR_TRACE` / `UNIFORM_DUMP` / `BLAS_PROBE` / `SNAPDUMP` (single-purpose debugging toggles, each a few lines).
**Still candidates (read before deleting, each is bigger than a switch):** `LL_VK_TEXONECOPY` (default off, measured gain nil: the C4 pixel handover path in `RKImageTex::PixelHandover` and `push_tex` mode 3), `LL_VK_ARENA=0` (is the non-arena buffer path still needed as a fallback?), `LL_VK_UI_SUBSTREAM` mode 2 (the persistent UI thread that ends in heap corruption, parked since F3), the `RK_VULKAN` guards (`#if defined(RK_VULKAN)`, `#if !defined(RK_VULKAN)` stub blocks: a build without Vulkan cannot work any more: mechanical), the `RKVkBridge` doc comments that still say "mirror" / "OpenGL".
**Checks:** after the three batches the beach run `f7b1-beach` equals the F3.6f baseline set (`FormatVerify`), 0 PassCheck / StateGuard / MatrixGuard warnings, 9.2 ms frames, 4,425 records, 0.41 ms queue writes (an earlier run after the first two batches, `f7a1`, read 10.7 ms and 0.87 ms: a repeat of the same build, `f7a2`, read 9.3 / 0.40 ms: scripted runs vary by that much, a same-session A/B is the only way to claim a change smaller than that). Picture judged by eye: `f7b1-beach-b.png` complete. `REGRESSION-CHECKLIST.md` has the F4 / texture items (13-22) and the guardcheck launcher sets the new check variables; `PLAN-gpu-scene.md` marks F3 / F4 / F5 done.

## London crowd baseline (candidate 2 measured first, 2026-10-20: the premise was wrong)
Scripted login at Last location = London (Soho / Regent's Park, 71 avatars in range), runs `f8a1-london` (counters) and `f8a2-london-zones` (`FS_CPU_ZONES=1`), build of 2a299d02. **The frame is 15.5-16.1 ms (65 fps); the main thread is the limit: it never waits for the worker (0.0 ms/frame) while the worker waits for work 3.0-3.2 ms/frame.** So optimizing the worker's per-draw cost or uniform application would not make London faster (at the beach the two threads are balanced, 9.3 ms).
