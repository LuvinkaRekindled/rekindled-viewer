# Carrying the Vulkan / DLSS work into a new Firestorm release

This branch (`vulkan-port`) is a set of local commits on top of Firestorm commit `4ae31a7a` (development branch, 2026-10-01, after tag `Firestorm_Release_7.2.4.80712`).
Nothing in it has been pushed anywhere. This note says what is in it, what usually conflicts, and the steps to move it onto a newer release.

## Things that live outside the repository

- **Vulkan SDK** (headers and the glslang / SPIRV-Tools libraries, which are linked statically): configure with `-DUSE_VULKAN=ON -DVULKAN_SDK_DIR=<sdk root>`. `USE_VULKAN` is OFF by default, so a checkout without the SDK still builds as plain OpenGL.
- **NVIDIA DLSS SDK** (optional, not redistributable, read its licence): clone <https://github.com/NVIDIA/DLSS>, then `-DDLSS_SDK_DIR=<clone>/DLSS`. Without it `llvkdlss.cpp` compiles to stubs. `nvngx_dlss.dll` (from `lib/Windows_x86_64/rel/`) has to be copied next to `firestorm-bin.exe`.
- **Build environment** (not in git): `fs-env.bat` (sets `AUTOBUILD_VSVER=170`, the variables file, the Python venv, `AUTOBUILD_CONFIG_FILE=my_autobuild.xml`), a local `my_autobuild.xml` that points at the FMOD 2.03.12 package, `build-run.bat`, `cmake-regen.bat`. Configure with `--fmodstudio --package --chan FSDev -DUSE_TRACY=ON` plus the two SDK options above, then `autobuild build -A 64 -c ReleaseFS_open --no-configure`.
- **Test launchers and tools** in `<work>`: `run-viewer-vulkan*.bat`, `vk-stack-sample2.ps1` (call-stack sampler with module attribution), `resolve-addr.ps1`, `vk-burst.ps1`.

## Generated code: the GL wrappers

`llvkgl.h`, `llvkgl_hooks.inc` and `llvkgl_async_dispatch.inc` are generated by `indra/llrender/tools/gen_llvkgl.py` (the list of hooked GL functions is the `FUNCS` table at its top).
Regenerating on the current branch produces no differences, so the script is the source of truth: edit the script, never the generated files.

## Porting steps

1. Fetch the new release tag. Create a branch from it: `git switch -c vulkan-port-<version> <tag>`.
2. Bring the groups over in order with `git cherry-pick` (or `git rebase --onto <tag> 4ae31a7a vulkan-port`). A first, then B, C, D, E. Group B conflicts first: re-do it by searching the new code for raw `gl*` calls outside `llrender` (`grep -rn "\bgl[A-Z][A-Za-z0-9]*(" indra --include=*.cpp` and look at what is not in `llrender`/`llwindow`) and route them through the `gGL` wrappers.
3. Run `python indra/llrender/tools/gen_llvkgl.py`. If upstream now calls a GL function that the mirror does not hook, the build or the `LL_VK_VERIFY` run will show it; add it to `FUNCS` and write its `on_<name>` hook in `llvkgl.cpp`.
4. Re-check the places where upstream often changes under us: render target formats (`llvkgl.cpp` format table), new shaders (they must compile through glslang: new GLSL features can fail), `LLVertexBuffer` and texture upload paths, new `settings.xml` defaults, and `LLPipeline::renderFinalize` (the DLSS call sits after the post chain).
5. Build, then run the checklist below.

## Checklist after a port

1. Plain OpenGL still works: start `firestorm-bin.exe` with no Vulkan setting.
2. `<work>\run-viewer-vulkan.bat`: login, a busy region, teleport, resize and maximise the window, snapshot preview and save, shadows/ambient occlusion on and off.
3. DLSS from the Preferences > Graphics > Vulkan tab (needs restart): name tags, crosshairs and their boxes hold still when you stand still; the log has `DLSS is ready` and `DLSS feature created`.
4. `run-viewer-vulkan-syncval.bat`: no new synchronization hazards in the `VulkanValidation` log lines (two known harmless ones: the shadow shader's unused colour output, and the PBR glow shader's unused input at location 3).
5. `run-viewer-vulkan-phases.bat` for numbers (`LL_VK_PHASES`): frame pacing, GPU time by pass, pipelines built.
6. Environment switches that revert behaviour if something looks wrong: `LL_VK_ASYNC=0` (inline mirror), `LL_VK_COARSE_BARRIERS=1`, `LL_VK_NO_DEVICE_BUFFERS=1`, `LL_VK_PIPELINE_CACHE=0`, `LL_VK_SPIRV_CACHE=0`.

## Known facts that save time

- The viewer can only be relinked with the viewer closed; the build also fails at the copy step (`media_plugin_cef.dll`) if it is running.
- The mirror presents into the main window and uses two command buffers per viewer frame (the frame and a small off-screen one after the present).
- The first DLSS run needs the NGX DLL; the DLSS checkbox only takes effect after a restart.
- `LL_VK_PHASES` timers slow the Vulkan thread and flip which thread is the bottleneck; use a plain run (and the stack sampler) when judging fps.
- Frame generation is not done; see `doc/vulkan/dlss-frame-generation-checklist.md`.
