# F3.2: the state vocabulary (design, 2026-10-19; nothing built yet)

Part of `F3-plan.md` (after F3.1, 23d31ba9 / c786e993). Everything below is counted from the code of 2026-10-19 (branch native-vk). F3.2 changes the **vocabulary** the pass code speaks for render state; the machinery behind it (one typed `LLVkState::Block`, one `CMD_STATE` record when it changes) is already done (F1.1). This is a refactor with no intended picture change.

## Where the state calls stand (measured)
- **The data is already typed.** `LLVkState::Block` holds native values (`RasterState`, `DepthStencilState`, `BlendState`, viewport, scissor). The producer functions in `rkvkstate.h` (`setEnable(U32 cap, bool)`, `setBlendFunc(4 GL factors)`, `setDepthFunc(GL func)`, `setCullFace(GL_BACK|GL_FRONT)`, `setPolygonMode(GL_FILL|GL_LINE)`, `setStencilFunc/Op(GL enums)`) take **GL enum numbers and translate them once** (`setEnable` is a `switch` on `GL_BLEND`, `GL_DEPTH_TEST`, `GL_CULL_FACE`, `GL_SCISSOR_TEST`, `GL_STENCIL_TEST`, `GL_POLYGON_OFFSET_FILL`, `GL_DEPTH_CLAMP`; all other caps fall to `default: break`).
- **The shadow of "what GL has" still exists in the viewer classes**, as a second copy of values the Block already holds:
  - `LLGLState` (`llgl.h/.cpp`): `static std::unordered_map<LLGLenum, LLGLboolean> sStateMap`; the constructor reads the map, `setEnabled` calls `gGL.flush()`, `LLVkState::setEnable(cap)`, writes the map; the destructor restores. Only `LLGLState` itself reads `sStateMap` (grep: no other reader). Cost: ctor+dtor 4.6-5.3k calls per frame, 0.05 ms (FRONT END counter, 9-10 ns per call).
  - `LLGLDepthTest`: three `static` shadows (`sDepthEnabled`, `sDepthFunc`, `sWriteEnabled`, initialised to the OpenGL defaults) used to skip identical writes and to restore in the destructor. `checkState()` and `LLGLState::checkStates()` are empty (38 call sites of `checkStates`).
  - `LLRender::blendFunc` keeps `mCurrBlend*Factor` and converts `eBlendFactor` (typed already) to a GL number with `sGLBlendFactor[]`, which `LLVkState::blendFactor()` converts again to the Vulkan value.
- **Call sites** (class names only; `LLGLSLShader` excluded): **554 uses in 75 files** (63 in newview, 6 in llui, 6 in llrender). `LLGLDepthTest` 173, `LLGLEnable` 124, `LLGLDisable` 93, `LLGLState` 69, `LLGLSUIDefault` 47, `LLGLSquashToFarClip` 10, `LLGLSPipelineAlpha` 8, `LLGLSPipelineSkyBox` family 17, `LLGLSDefault` 6. Heaviest files: `pipeline.cpp` 117, `llviewerdisplay.cpp` 37, `llglstates.h` 39 (the preset classes), `fsmaniprotatejoint.cpp` 26, `llviewerwindow.cpp` 21, `llspatialpartition.cpp` 21, `llmaniptranslate.cpp` 20, `llglsandbox.cpp` 14, `llmaniprotate.cpp` 13, `llmanipscale.cpp` 11, `lldrawpoolalpha.cpp` 11, `llhudtext.cpp` 9.
- **GL enum names that are state vocabulary** (what F3.2 removes; counts of uses in newview + llui + llrender): `GL_BLEND` 94, `GL_FRONT_AND_BACK` 69, `GL_CULL_FACE` 67, `GL_FILL` 39, `GL_LINE` 31, `GL_ALWAYS` 27, `GL_STENCIL_TEST` 19, `GL_POLYGON_OFFSET_FILL` 19, `GL_LEQUAL` 16, `GL_GREATER` 15, `GL_KEEP` 12, `GL_POLYGON_OFFSET_LINE` 8, `GL_ZERO` 7 and the stencil ops: about 430 of 2,097 `GL_` uses. The rest of the `GL_` uses are **not state** and belong to other steps: shader types (300), texture / buffer targets and formats (F3.4, F3.6), `GL_TRUE`/`GL_FALSE` (330, mostly shader and bool arguments), clear bits, driver strings.
- **Direct state setters**: `setPolygonMode` 68 (every call is `GL_FRONT_AND_BACK` with `GL_FILL` 36 or `GL_LINE` 27; the face argument is ignored in `LLRender::setPolygonMode`), `setCullFace` 16 (`GL_BACK` 5, `GL_FRONT` 4, variables 2), stencil 38 (`GL_KEEP`/`GL_REPLACE`), `setColorMask` 91 and `setSceneBlendType` 41 / `blendFunc` 11 (already typed), `setLineWidth` 100 and `setPolygonOffset` 40 (floats), viewport 29 / scissor 13 (ints): these need no vocabulary change except the three that carry GL enums.

## Target
A header without GL (`rkrenderstate.h`, namespace `LLRenderState`; the only new file) holds typed enums and **scoped guards that save and restore the field in the producer's Block** (no map, no statics):
- `enum class CullFace { None, Back, Front }`, `PolygonMode { Fill, Line, Point }`, `CompareOp { Never, Less, Equal, LessEqual, Greater, NotEqual, GreaterEqual, Always }`, `StencilOp { Keep, Zero, Replace, IncrClamp, DecrClamp, Invert, IncrWrap, DecrWrap }`; blend factors are `LLRender::eBlendFactor` (exists).
- Guards, all `flush()` first when they change something (pending immediate vertices belong to the old state: this stays): `BlendScope(bool)`, `CullScope(bool on, CullFace face = Back)`, `ScissorScope(bool)`, `StencilScope(bool)`, `PolygonOffsetScope(bool)`, `DepthScope(bool test, bool write = true, CompareOp = LessEqual)` (the replacement of `LLGLDepthTest`, same defaults and the same "no depth writes without the test" rule), `DepthClampScope`.
- Setters take the typed values: `setCullFace(CullFace)`, `setPolygonMode(PolygonMode)` (no face), `setStencilFunc(CompareOp, ref, mask)`, `setStencilOp(StencilOp x3)`, `setDepthFunc(CompareOp)`.
- The **preset classes of `llglstates.h`** (`LLGLSUIDefault`, `LLGLSPipeline`, `LLGLSPipelineAlpha`, `LLGLSPipelineSkyBox` ..., `LLGLSObjectSelect`, `LLGLSTracker`, `LLGLSDefault`) keep their names and become bundles of the typed guards (a rename can follow, it is not needed).
- At the end `LLGLState`, `LLGLEnable`, `LLGLDisable`, `LLGLDepthTest` (+ `sStateMap`, `llglstates.h` constants, `LLGLState::checkStates/dumpStates/resetTextureStates/restoreGL` statics, the 38 `checkStates` calls) and the GL-number overloads of `LLVkState` are deleted. `LLVkState::blendFactor/compareOp/...` take typed values and write the Vulkan value directly (the GL -> typed table in `rkvkformat.cpp` stays only for what F3.6 still needs).

## How the sites change (mechanical, one script)
The two shapes cover nearly all sites: `LLGLEnable x(GL_BLEND);` -> `BlendScope x(true);`, `LLGLDisable x(GL_CULL_FACE);` -> `CullScope x(false);`, `LLGLState x(GL_BLEND, enabled);` -> `BlendScope x(enabled);`, `LLGLDepthTest d(GL_TRUE, GL_FALSE, GL_LEQUAL);` -> `DepthScope d(true, false, CompareOp::LessEqual);`. Three shapes need care (read them, do not script them): the **conditional cap** (`LLGLDisable cull(cond ? GL_CULL_FACE : 0)`: cap 0 means "no change"; 14 sites: `gltfscenemanager.cpp` 665 and 1100 (`LLGLState blend(GL_BLEND, i == 0 ? ...)`), `lldrawpool.cpp` 1346, `lldrawpoolalpha.cpp` 367, 654, 701, 798, 817, `llface.cpp` 671 (`LLGLDisable depth(wireframe_selection ? 0 : GL_BLEND)`: named depth, disables blend), `llvieweroctree.cpp` 1220 and `pipeline.cpp` 14069 (`GL_DEPTH_CLAMP`), `pipeline.cpp` 6853, `llviewerwindow.cpp` 5189 (`GL_MULTISAMPLE_ARB`: no effect in the Block, becomes nothing)) -> a guard with an `active` constructor argument that changes nothing when false; a guard that is **turned on or off after construction** (`mScissorState.setEnabled(...)` in `lllocalcliprect.cpp`; none uses `CURRENT_STATE`). The script lives next to the notes (`<work>\f32-migrate.py`, written in the first step of the next session), runs per file group, prints what it did not touch, and the build proves the rest.

## Gates (the F3-plan.md ones plus these)
`state` records per frame equal to the references (343 per frame in the crowd spot; a difference means a guard changes more or less than the class it replaced); `unknown command` 0; FRONT END `LLGLState` counter replaced by a guard counter (calls/frame about the same, ns per call lower than 9-10: no hash map); pictures of the spot of each family against the references taken before the step; `LL_VK_STATE_GUARD_CHECK=1` run with 0 warnings before a group is committed (or each warning explained). Expected gain: vocabulary only (the front-end counter shows 0.05 ms), no picture change; state the numbers measured in each commit message.

## Risks
- **Statics drift.** `LLGLDepthTest` restores from its own static copy; a path that sets depth state through `LLVkState` directly (render targets, `LLRender::setScissor`...) leaves the static stale, so the destructor restores a value the viewer did not have. The Block-based guard restores what the Block really held, which is the correct behaviour and can change a picture where a pass relied on the stale restore. The guard check above finds these; each one is a bug fix to be named in its commit, not hidden.
- **Conditional guards** (cap 0) and guards that outlive their scope through `setEnabled`: read, not script.
- **The flush before each change** must stay in the guards (pending immediate vertices draw with the state of the flush, not of the vertex call).
- **No old path to A/B**: pictures against references only; manipulator, selection and debug overlays need Adam to look (he has the list from F3.1).
