# U design note (2026-10-21): the pass uniform block for the deferred programs

Status: DESIGN for review. No code. Follows S3 (`S3-handoff.md` part 4: after the table path, what is left of `renderGeomDeferred` is the pass setup, not the geometry). Foundation background: `F0-inventory.md` section 2 (uniforms by how often they change), `F2-draw-records.md` F2.5 (class blocks), `POST-F-REVIEW.md`.

## 1. What exists already (read from the code)
- **Class blocks per program (F2.5, done).** Every program has up to five std140 blocks (`UC_PASS`, `UC_DRAW`, `UC_MATERIAL`, `UC_LIGHT`, `UC_SKIN`, bindings 0 and 5-8, `rkvkshader.h`); the producer keeps a copy per shader (`mVkShadow`), `uniform*()` resolves a write to bytes in it, compares, and sends only a changed range (`CMD_UNIFORM_RANGE`); the worker copies a class block to the uniform ring only when something in it changed. So "the pass uniforms of a program" are already one block that is only copied when a value changed; there is **no** per-draw 13 MB copy any more.
- **Pass uniforms are set per program bind, by the viewer:** `LLPipeline::bindDeferredShader(shader, light_target, depth_target)` (pipeline.cpp:14111-14380) makes about 45 setter calls (viewport, 6 shadow matrices, shadow clip, sun wash, shadow noise, blur size, 5 SSAO values and a 3x3 matrix, screen res, near clip, shadow offsets / biases, sun / moon dir, shadow res, edge cutoffs, two delta matrices, cube snapshot, norm matrix, sun / moon colour, probe max lod), ~20 texture bindings (`enableTexture` + `bindTexture` / `bindManual` for the G-buffer, depth, exposure, noise, light function, light target, 6 shadow maps, probes) and `bindReflectionProbes` (the probe UBO by `bindUniformBlock`, `setEnvMat`). It runs for every deferred program the passes bind: the 12 materials pull programs (plus 12 rigged variants before S3 G4), sun / soften / blur / light / multi-light / haze / water / avatar / alpha variants (`bindDeferredShaderFast` re-binds only the textures when the program was fully bound before: `mCanBindFast`, used by the alpha pool only).
- **The pull programs are ours** (`deferred/diffusePullV.glsl`, `materialPullV.glsl` + the stock fragment shaders with `RK_BINDLESS_*`): their pass uniform set is whatever the fragment shaders and their includes read.

## 2. What the numbers say (London, `g4-ab1`, current build)
- Front end per frame (VkOps line): `uniform*` 27.7k calls 0.54 ms (19 ns each), `uniformMatrix*` 4.1k calls 0.31 ms (76 ns), `RKShaderProgram::bind` 1.2k calls 0.15 ms, `LLTexUnit::bind` 1.7k 0.06, `bindManual` 7.2k 0.08: **about 1.1 ms of the render front end is uniform / bind / texture binding work, for all passes together** (lights, alpha, UI, post included). 23k of the 27.7k uniform calls end in a sent range write.
- Where the changes come from (F0 measurement, Oct 10, same classes): per light draw 3.7k changes / frame, per draw 1.0k, per material 0.8k, skin palette 0.7k, **per pass / per view only 0.57k** (263 uniforms). The pass class is the smallest class by changes.
- `pool: materials` is 0.38-0.40 ms in 25 calls (12 static passes now, the rigged ones skipped), about 30 us a static pass: a `bindDeferredShader` of a pull program plus `pushGeometryPackets` (now only the table record). The setter calls alone at 19-76 ns cannot be 30 us (45 calls ~ 1.5 us): so **the cost of a pass bind is not demonstrated to be the uniform calls**; texture binds (~20 per bind, each with a map lookup in `enableTexture`), `LLEnvironment::getCurrentSky()` (a shared_ptr copy) and the shadow matrix copy loop per bind are the other suspects. No zone exists inside `bindDeferredShader`, so the split is unknown. Theoretical bound by calls: even eliminating every pass setter of ~50 distinct program binds a frame saves 50 x 45 x 20 ns = 0.05 ms.

## 3. Options (decided by step U0)
- **U1, viewer only: split and cache.** `bindDeferredShader` -> `bindDeferredTextures(shader, targets)` + `applyPassUniforms(shader)`. The pass values are a plain struct built from members and cached controls (about 600 bytes, built once a frame and again only when a source changes: a version counter bumped by the places that set `mSunShadowMatrix`, `mSunClipPlanes`, sun dir, the delta matrices, `gRenderViewport`, the target sizes, `gCubeSnapshot` / `sReflectionRender`, the `Render*` cached controls' change callbacks); each program remembers the struct version it was last written with, and `applyPassUniforms` returns at once when it equals the current one. The textures part stays per bind (targets differ per call site) but loses its map lookups by caching the program's channel numbers. No shader change, no worker change. Gate: pictures identical, uniform calls per frame lower by the setter count, `bindDeferredShader` ns lower. Risk: a source of the pass values that is missed gives a stale uniform for the programs bound after it in the same frame: verify mode = run the old setters into the producer copy of a second program set and compare the class block bytes after each bind (like F2.5's `mShadowNew` verify).
- **U2, shader level: a pass UBO.** One `DeferredPass` std140 block (a struct with those ~45 values) written once per pass epoch into a UBO, bound with the existing `gRender.bindUniformBlock(UB_...)` (the probe UBO already works this way), read by the fragment shaders instead of loose uniforms (edit `deferredUtil.glsl` and the programs that include it; the programs' loose `uniform` declarations go away for these names). The producer writes the block once (a few hundred bytes compared against the last one), the per-bind uniform work is zero, the worker's per-program pass class blocks of those programs shrink. This is the "pass block" of the foundation plan; it is only worth its shader churn if U0 shows the uniform part is the bulk of the bind.
- **U3, per-bind elimination.** Passes that bind the same program set every frame in the same order (the 13 pulls, sun / soften / blur) could bind once per frame with a pre-resolved texture set (the bindless table makes a texture set a few integers: the pulls already pass slots in the entries). Needs U1/U2 first; the lighting passes are not S3's.

## 4. Step U0 (no behaviour change, one build, one batch of runs): measure what a pass bind costs
Instrumentation two levels deeper than the question needs, so one run answers U1 vs U2 vs "not uniforms":
1. Inside `bindDeferredShader`: ns per section (shader.bind, G-buffer / depth / exposure / noise texture binds, light function, light target, shadow map binds, shadow matrix loop + uniform, env map, `bindReflectionProbes`, the 40 scalar / vector uniform lines, the delta / norm matrices, `getCurrentSky` + sun colour) as accumulated counters, and **per program** (key = program name): binds a frame, ns per bind, uniform calls per bind (a counter in `mirrorScalar / Vector / Matrix` read before and after), range writes sent, texture binds per bind. Printed every 600 frames, top 20 programs.
2. Per pass of `LLDrawPoolMaterials::renderDeferred` and per pool of `renderGeomDeferred`: ns split into bind, `pushGeometryPackets` (build wait, finish, table record), fallback draw, the rest; counts of binds skipped by the S3 G4 lazy rule.
3. A global uniform call census by source: a thread-local "scope tag" set at the big sites (each deferred pool, the light loops, the alpha pool, shadow passes, UI, post): calls, changed, ns by tag, so the 27.7k calls are attributed.
4. Frame-level A/B inside one login for the next steps stays the `LL_VK_SCENE_GEO_AB` style: a live phase switch for the U1 skip (`LL_VK_PASSUNI_AB=<s>`) so the first run after U1 already carries its own comparison.
Output of U0: a table "where the 1.1 ms front end goes by pass and by cause" and a recommendation (U1, U1 then U2, or stop: if the pass bind is mostly texture binding, the lever is a cached texture set, not uniforms).

## 5. Gate and honest expectation
Gate (per step): pictures identical (alternation shots, difference below the on-on noise), 0 verify mismatches, main thread `pool: materials` + the lighting passes' bind cost lower by the measured part, worker unchanged or lower. Expectation stated before measuring: the whole uniform / bind front end is 1.1 ms; pass setup of the deferred programs is probably 0.2-0.4 ms of it; U1 might recover half, U2 most. Not expected: a change in GPU time or in picture.

## 6. Decision for Adam
Go for U0 (instrumentation only, no behaviour change, one build and one batch of runs), then choose U1 / U2 from its numbers. Alternative: skip to U1 directly (cheaper to build, but the same measurement would still be needed to know what it bought).

## 7. U0 results (2026-10-21, London, 90+ avatars, `LL_VK_UNICENSUS=1` with `FS_CPU_ZONES=1`; runs `u0-a` table serving, `u0-b` old path, `u0-c` serving without the census = the time baseline)
Instrumentation: `rkuniformcensus.h` (header only, off unless `LL_VK_UNICENSUS=1`), hooks in `RKShaderProgram::mirror*` / `vkSendRange` / `vkWriteFloats / vkWriteMatrix` / `bind`, `LLTexUnit` bind functions, `RKCpuZoneScope` (attribution to the innermost CPU zone), laps inside `LLPipeline::bindDeferredShader`, zones in `LLDrawPoolMaterials`. Log tag `UniCensus` every 600 frames: totals, by innermost zone, `bindDeferredShader` by program with section times, by class, by uniform name, by program. Census overhead: the loop interval is 1.6 ms higher with it (18.2 against 16.6 ms): read the **counts** from `u0-a` / `u0-b`, the **times** from `u0-c`.
**Totals per frame:** 29.1k uniform writes (7.0k changed, 1.26 MB of ranges), **32.3k texture binds**, 1.6k shader binds, 235 programs seen (old path `u0-b`: 26.5k writes, 29.5k texture binds). By class: **pass 12.3k writes / 495 changed (96 % redundant)**, material 8.0k / 1.0k, light 6.1k / 4.0k, draw 1.4k / 0.7k, skin 1.3k / 0.8k.
**What a deferred pass bind costs (`u0-c`, no census overhead):** `bindDeferredShader` 0.13 ms for 52 calls a frame (2.5 us each; 1.6k writes, 1.05k texture binds in them); the pull programs 7 us each with the census (sections: gbuf 1.3, probes 1.7, shadow matrix 0.8, delta / norm matrices 1.1, tail 0.6 us; the uniform parts are about 40 %). **So the whole pass uniform setup of `bindDeferredShader` is 0.13 ms; the part U1 or U2 could remove is at most 0.05 ms: the hypothesis of the design note (section 2) is confirmed, U2 is not worth its shader churn.**
**Where the time really is:**
- **`bindDeferredShaderFast` 0.35 ms (u0-c), 1,029 calls a frame**, all from the alpha pool (one per draw group): **8.4k uniform writes and 19.5k texture binds a frame** (18-19 binds and about 8 writes per call: light function, BRDF LUT, 6 shadow maps, 3 probe textures, env matrix; 3 % of the writes change). `post pool: alpha (post water)` is 1.56 ms in total (1.1 calls), the biggest single piece of the render front end; it holds 6-8k of the 29k writes and 5-7k of the texture binds (rigged alpha: `Skinned Material Shader 29 / 21` bound 315 / 275 times a frame with 6.7k / 3.6k writes).
- **`pool: materials` 0.41 ms is not the bind** (bind + packets sub-zones are each below 0.06 ms): it is the rigged material passes that still run (3-4 a frame, the avatar draws: per draw `specular_color` 2.2k writes (420 changed), `env_intensity` 2.0k (83), `emissive_brightness` 2.0k (18), `minimum_alpha` 0.6k (100), `matrixPalette` 1.3k (755 changed)).
- **Lights:** `lighting: projectors` 3.8k writes (1.9k changed) 0.10 ms + `local lights` 1.5k writes 0.30 ms: the light class is the only class whose writes mostly change (4.0k of 6.1k): inherent to per-light uniforms, a light buffer would remove the writes (S-light, not a pass block).
- Pass class by uniform name: `depthRejectBias, ssrTraceMode, iterationCount, distanceBias, glossySampleCount, rayStep, adaptiveStepMultiplier` 975 writes each, 0 changes (40 programs bound by the Fast path), `classic_mode` 584 / 0, `env_mat` 975 / 5, `rt_sun_*` 159 / 0, `ambient_color`, `sunlight_color`: all constant within a frame.
**Recommendation: U1 re-scoped (viewer only, no shader change), not U2.** Target the measured redundancy, in order: (1) `bindDeferredShaderFast` (0.35 ms, 8.4k writes, 19.5k texture binds): skip what is already current (per-program stamp of the last full bind and a frame / pass epoch; the shadow map, probe, light function and BRDF LUT bindings and the pass uniforms only change when the pass state does; verify mode = the old path into a second copy, compare, as F2.5 did). (2) the redundant pass-class setters of `bindDeferredShader` (a pass struct built once and compared, 0.05 ms, only after (1)). (3) the per-draw material setters of the rigged and alpha pools (compare before the call: `specular_color`, `env_intensity`, `emissive_brightness`, `minimum_alpha` are written 2k times a frame for 18-420 changes). Expectation: 0.4-0.6 ms of main thread (about 3 %), no GPU or picture change. What U1 cannot do and the next slices must: the alpha pool as a whole (1.6 ms: S5), the rigged avatar draws (S4), lights (a light buffer).

## 8. U1 (re-scoped) design (2026-10-21, before code)
Scope: viewer side only, no shader change, pictures identical. Three parts, in the order of the measured redundancy (section 7).

**Facts read from the code that shape it**
- A texture bind is already deduplicated per unit (`LLTexUnit::bindManual / bind`: `mCurrTexture != texture`), so a redundant bind writes nothing; its cost is the call chain (`enableTexture`, `getTexUnit`, `FrontLap`, `gRender.flush()`), about 10-15 ns each. A uniform write is already compared against the producer's class block copy (`vkWriteFloats`, `vkDiffCopy`), about 19 ns; `uniformValueChanged` is a stub. So compare-before-call saves the call chain only: the honest bound of the whole U1 is `bindDeferredShaderFast` 0.35 ms minus what must stay (`shader.bind()` 1,030 times, about 0.13 ms) plus about 0.1 ms of per-draw setters, i.e. **0.25-0.35 ms**, below the 0.4-0.6 of the census recommendation. Stated before measuring.
- `bindReflectionProbes` steps `mPoissonOffset` and writes `ssr_noise_sine` on **every** call (a deliberate per-draw-group noise value, 1,030 changes a frame): the skip must keep that exactly (one increment + one write per call, same sequence), or the picture changes.
- Texture units are global (`gRender.mTexUnits[32]`), channel numbers are per program, so another program's Fast bind or a draw's own texture can write unit N between two Fast binds of program P: the skip must be per unit, not a flag.

**Part 1: the Fast path skip (`bindDeferredShaderFast`)**
- Pass state struct `FastState` (POD, about 40 words) built on every Fast call from the same sources the old binds read: GL names of the light function, BRDF LUT, shadow targets 0-3 (depth), spot shadow 4-5, probe / irradiance / hero cube arrays, scene map colour + depth, the probe UBO id, `sReflectionProbesEnabled`, `RenderMirrors`; and the values the Fast path writes: the 3x3 env matrix from `gRenderModelView`, the six `RenderScreenSpaceReflection*` values, the trace-mode bits. It is `memcmp`ed with the previous one; a difference bumps a version (`mFastVer`). No hand-placed epoch bumps: any source that changes is seen by value, so nothing can be missed by a forgotten site.
- Per program: `mFastVer` (the version of its last full Fast fill), `mFastSeq` (global texture-unit write sequence at that time) and the list of the units its pass samplers use (recorded in the fill from the `enableTexture` results, at most 16).
- Global texture-unit write stamps: `rk_bindTexUnit_impl` (the single funnel of every slot write) sets `sUnitStamp[unit] = ++sWriteSeq`.
- Hit = `mCanBindFast && mFastVer == version && no unit of the list has a stamp newer than mFastSeq`. Hit does: `shader.bind()`, the poisson step + one `ssr_noise_sine` write. Anything else = the old fill, then record version, seq and the units.
- **Verify mode** `LL_VK_PASSUNI_VERIFY=1`: on a predicted hit, the old fill is run too (poisson step not repeated) and compared: the five class blocks of the program (`mVkShadow`) before / after, and `getCurrTexture()` of every unit in the list before / after. Counters: hits, misses by cause (version, unit stamp, not bound before), mismatches (printed once with program name, uniform class, unit). 0 mismatches over a long run before the skip is used without verify.
- Switch `LL_VK_PASSUNI=1` (off by default; setting later), live A/B `LL_VK_PASSUNI_AB=<s>` with the log marker `[phase] pass uniform skip now ON/off`, same as `LL_VK_SCENE_GEO_AB`.

**Part 2: pass-class setters in `bindDeferredShader`** (45 calls, 0.05 ms, only 495 of 12.3k pass writes change): after part 1 the Fast path no longer reaches them; the remaining 52 full binds a frame are 2.5 us each. Built as the same `FastState` idea only if part 1's numbers leave it worth it (decided from the post-U1 census; not before).

**Part 3: per-draw setters in the alpha pool** (`specular_color`, `env_intensity`, `emissive_brightness`, `minimum_alpha`, `matrixPalette` compare): compare the new values with the last ones written to the same shader in the pool lambda (a small per-shader cache reset by shader bind / `prepare_alpha_shader`) and skip the call; the rigged materials pool the same. Verify mode: the cached compare is checked against the producer copy (the call is made, and the class block must not change when the cache said skip).

**Instrumentation (two levels deeper than the question)**: per frame counters of Fast calls, hits, misses by cause, the part-3 calls made / skipped by uniform name, time in the Fast function split into bind, state build, fill, verify (zones `bindDeferredShaderFast` / sub-zones); the existing census (`LL_VK_UNICENSUS=1`) for write and bind counts; A/B windows for time.

**Gate**: pictures identical (on / off shots difference <= on / on noise, eyes), verify 0 mismatches, writes and texture binds per frame down by the redundant part (about 8k writes / 19k binds from the Fast path), `bindDeferredShaderFast`, `post pool: alpha (post water)`, `pool: materials` and the loop interval lower by what the census predicts (0.25-0.35 ms), GPU equal.

## 9. U1 status (2026-10-21): built, verified, measured in a small scene (the plaza was not available); gain real but small
**Built** (`LL_VK_PASSUNI=1` skips, `LL_VK_PASSUNI_VERIFY=1` verifies, `LL_VK_PASSUNI_AB=<s>` alternates with the marker `[phase] pass uniform skip now ON/off`; all off by default): `LLPipeline::bindDeferredShaderFast` (pipeline.cpp) with the by-value pass state (`PassFastState`, version), per-program record (`mFastVer`, `mFastSeq`, `mFastUnits`), texture unit write stamps (`LLTexUnit::getUnitStamp` / `getWriteSeq`, set in the single slot-write funnel), `bindFastUnit` (the rebind of only the units written since), `stepPoissonOffset` (the per-bind noise step kept exactly), the cube array stage set by hand on a skip; the alpha pool's per-draw `specular_color / env_intensity / emissive_brightness` are written only when they differ from what the loop last wrote to the program in the epoch (`mAlphaVals`, `sAlphaEpoch`, bumped at each `renderAlpha` and after the emissive passes). Not done: `minimum_alpha` (0.6k calls = 0.01 ms, not worth a cache) and `matrixPalette` (already has its own last-avatar skip); part 2 (the 45 pass setters of `bindDeferredShader`: 51 binds a frame, left alone).
**Verify** (`u1-v`, 150 s, 1.15 M verified Fast binds, 79 % of them skipped or partly rebound): **0 mismatches** in class blocks, texture unit contents and cube array stages; alpha setters verified likewise (0 mismatches). Skips were never rarer than expected: per frame in that scene 92 Fast calls, 12 full fills (the per-call `prepare_alpha_shader` reset), 34 full skips, 45 skips that rebind units (all 11 sampler units: the pass sampler units differ between programs, so two programs alternating overwrite each other's units: the texture unit design, not a missed state).
**Counts** (`u1-cs0` off, `u1-cs1` on, 85-106 Fast calls a frame, census): uniform writes **9,558 -> 8,505 a frame (-11 %)**, texture binds 5,918 -> 5,564 (-6 %; a rebound unit is still a bind call, the saving is the skipped ones), in the Fast zone itself writes 629 -> 76. London (1,030 calls) would scale about 12x on the Fast part (the 8.4k writes there are mostly this); not measured.
**Time** (A/B 20 s phases, pure windows, `u1-ab1/2/3`, loop interval 9.8-11 ms, 9-10 windows each): `bindDeferredShaderFast` 0.049 -> 0.037, 0.040 -> 0.031, 0.042 -> 0.031 ms (**-0.010 ms**, 25 %); `post pool: alpha (post water)` 0.269 -> 0.226, 0.186 -> 0.169, 0.197 -> 0.174 (**-0.02 to -0.04 ms**); loop interval -0.27, +0.11, -0.14 ms (noise: the windows move by more than that). GPU 4.84 off / 4.91 ON per command buffer (inside noise, no GPU work changed). Per call the saving is 0.1 us; at London's 1,030 calls that is about **0.1-0.15 ms** of the 0.35 the census called Fast, plus a part of the alpha setters: the honest total is **0.15-0.25 ms, under the 0.4-0.6 the census recommendation expected**. The reason is the one stated in section 8 before measuring (the bind and the unit rebinds that must stay, calls already deduplicated per unit) plus the unit thrash above.
**Pictures:** whole-window mean abs difference of the ON / OFF shots 12-14 s after a flip is 3.2 / 2.3 against 4.0 / 2.6 between two shots of the same state (`u1-ab1`, `u1-ab2`, 15 + 16 shots); eyes: right.
**What would make the skip bigger (not built):** a fixed unit for each pass sampler in every deferred program (shader side: the alpha programs declare the samplers in their own order) so the units stay current across programs; or bindless pass textures (S5). Check in the plaza (90+ avatars) for the real gain before more work here. Runs: `<work>\run-logs\u1-*.log`; `AB_MARK='[phase] pass uniform skip now' python <work>\ab_zones.py <log> 60`.

## 10. U1 in the plaza (2026-10-21, runs `u1p-v`, `u1p-ab`; a lighter crowd than the census: 380 Fast calls a frame, loop interval 12.7 ms)
**Verify:** 3.75 M verified Fast binds (97 % skipped or partly rebound: 141 of 380 calls a frame rebind all 11 sampler units), alpha setters made 192 / skipped 785 a frame: **0 mismatches**, no device lost. **A/B** (20 s phases, 7 + 8 pure windows): `bindDeferredShaderFast` **0.135 -> 0.080 ms (-41 %)**, `post pool: alpha (post water)` **0.718 -> 0.630 ms (-0.09 ms)**, `bindDeferredShader` / `pool: materials` / `renderGeomDeferred` unchanged, loop interval 12.85 -> 12.61 ms (-0.24, inside the window noise), GPU 5.99 -> 6.05 ms (equal). Per Fast call the saving is 0.145 us: **0.15 ms at 1,030 calls**, plus the alpha pool's setters: the real total is about 0.1-0.2 ms of main thread, as estimated in section 9. Not a step to push further on its own; the next lever is fixed pass sampler units or bindless pass textures (S5).
