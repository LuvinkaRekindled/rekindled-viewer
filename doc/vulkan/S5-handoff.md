## 5. S5 (alpha pass from the scene): research done, nothing built, no design note yet
Plan text: "S5. Alpha pass from the scene (GPU sort, indirect), emissive second draw folded in." Per the order Adam agreed, S5 is next; start with a design note (facts, options in order, expected gain, gate) and ask his decisions before code, as for S3 / S4.

**Facts read (`lldrawpoolalpha.cpp`, `pipeline.cpp`, `llvovolume.cpp`):**
- The alpha pools: `POOL_ALPHA_PRE_WATER`, `POOL_ALPHA_POST_WATER`; `renderPostDeferred` primes the shaders (`prepare_alpha_shader` for emissive, PBR glow, fullbright alpha mask, simple, every `gDeferredMaterialProgram[SHADER_COUNT*2]`, PBR alpha) then `forwardRender(rigged=true)` (rigged first, writes depth), `forwardRender()` (static), an optional fringe pass (`forwardRender(true, true)`: soft part of rigged alpha, polygon offset, depth LESS), and, post water with depth of field, a depth-only `renderAlpha` pass. `renderAlpha(mask, depth_only, rigged)` is the loop.
- Order: `postSort` sorts `sCull->mAlphaGroups` by distance (`LLSpatialGroup::CompareDepthGreater`, back to front) and the rigged alpha groups by avatar attachment order (`CompareRenderOrder`); inside a group the draw infos keep the order `genDrawInfo` made (faces sorted by `LLFace::CompareDistanceGreater` for alpha, `llvovolume.cpp:6736`; particles sort in `llvopartgroup.cpp`). **Blend order is part of the picture: any scene-driven version must keep the group order and the in-group order.**
- Per draw today: `applyModelMatrix`, shader choice (PBR blend: `pbr_shader`; fullbright: `fullbright_shader`; material: `gDeferredMaterialProgram[mShaderMask]`; else `simple_shader`; rigged variant via `mRiggedVariant`; HUD / impostor variants), `bindDeferredShaderFast` on change (U1 skips redundant writes), spec colour / environment intensity / brightness uniforms (U1 compares), rigged: `uploadMatrixPalette`, `TexSetup` (diffuse by `mTextureList` batch of up to 4 or single; normal + specular maps for materials; `mTextureMatrix` loaded into texture matrix 0; glTF: `mGLTFMaterial->bind`), per draw `blendFunc(params.mBlendFuncSrc/Dst)` and a `setMinimumAlpha(0)` / reset for custom blend functions, `drawRange`, then **a second glow draw** (blend ZERO/ONE, ONE/ONE; emissive buffers) collected per group (`emissives`, `rigged_emissives`, `pbr_emissives`, `pbr_rigged_emissives`) and drawn after the group. Cull is off (double sided glTF handled by a `CullScope`). Particle partitions (`PARTITION_PARTICLE` / HUD particle) go through the same loop with culling disabled.
- Cost today (London): 2,872 alpha draws and about 1.2 ms of main thread a frame for the post-water pool, 1,029 `bindDeferredShaderFast` calls a frame (8.4k uniform writes, 19.5k texture binds before U1), the alpha builder for shadows is separate (`packets: shadow alpha` 0.45-0.49 ms + wait 0.25). `lighting: post-deferred geometry` is 1.9 ms in all (alpha is most of it).
- What exists to reuse: S3 persistent fragments with pins / events (G entries per draw info, `scene_geo_fill`, 160 byte rows, bindless textures), the pull programs (`diffusePullV` / `materialPullV` and the skinned variants), `drawPackets` / `drawPacketsIndexed` (indexed runs matter for skinned meshes: non-indexed pull cost +0.8 ms GPU), per-frame palette bindings (S4 B), moving matrix slots (S4 C), shadow alpha packets and resident alpha (`scene_alpha_on`) for the shadow side.
- Hard parts to design: (1) state runs: the sequence must keep program + blend func + cull + depth state per draw, so the GPU-driven form is runs of consecutive draws with equal state, one indirect command per run; the run count decides the gain (needs a census); (2) the alpha shaders are forward-lit with many uniforms (sun shadows, lights, fog, water clip sign), so pull versions of about 6-10 programs (simple, fullbright, material masks, PBR, rigged variants, impostor / HUD stay on the old path); (3) per-draw values (spec, env, brightness, min alpha, blend, texture matrix, glTF material block) must move into the table row; (4) the glow second pass and the rigged depth / fringe passes; (5) HUD, impostors, reflection probes, mirrors and the depth-of-field pass keep the old path; (6) particles' vertex data is rewritten every frame.
- **Suggested first step (A0, log only):** census of the post-water alpha draws by class (simple / fullbright / material mask / PBR / rigged / particle / emissive second draw), run lengths of equal (program, blend, cull) in the real order, textures per draw, how many draws are served by fragments vs. built per frame, and the main-thread split of the 1.2 ms (shader binds, TexSetup, uniforms, draw call). Then decide between: S5a = fragments + pull programs for the plain `simple_shader` / `fullbright_shader` runs only (static, non-rigged, no glTF) with the old path for the rest; S5b = materials / PBR; S5c = rigged; S5d = glow second draw and GPU sort.
- Expectation to state honestly in the note: the pool is about 1.2 ms main thread of an 11-12 ms display(); like S3 / S4, a table will remove the per-draw CPU work but not the group sort and the in-group order, so a realistic gain is 0.5-0.9 ms main thread, GPU equal.
