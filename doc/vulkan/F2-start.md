# F2 executor: status and steps

F2 turns the worker (`llvkgl.cpp`, `llvkasync.cpp`) from "the GL mirror" into the executor of the typed records. Measured on the plaza before F2 (F1.6 build): the worker is the bottleneck (24.4 ms busy of 24.8 ms per frame); 7816 draws at 2.3 us = 17.8 ms, of which renderer apply+record 12 ms (uniforms 3.5, sampler slots + ray scene set 1.5, texture layouts 0.7, pipeline 0.5, vertex input 0.4), shadow packets 2.3, rt scene 2.1, present 0.5. The stream is typed already (about 16k records/frame); what is left of "GL" in the worker is its tables keyed by GL names with GL enums in them, and the GL-named handlers.

## F2.1 done: no hook layer (2026-10-10)
- Resource lifetime is two typed records: `CMD_RESOURCE_CREATE/DESTROY` (`LLVkAsync::resourceCreate/resourceDestroy(kind, n, ids)`, kinds texture / target / buffer / query; the names are handed out on the producing thread, the objects made / released in stream order; inline mode before the queue starts runs them under the lock). `LLVkTex/LLVkTarget/LLVkBuf/LLVkQuery::create/destroy` call them.
- The 9 GL texture-edit hooks and their encoders are gone; the worker's handlers keep their bodies as plain functions (`edit_image2D/3D`, `edit_subimage2D/3D`, `edit_compressed2D`, `edit_param_i/f/iv`, `edit_mipmap`; `create_*/destroy_*` for the lifetime), reached only from the typed `tex_*` entry points and `resource_create/destroy`.
- Deleted: `gen_llvkgl.py`, `llvkgl_hooks.inc`, `llvkgl_async_dispatch.inc`, the generated `llvkgl.h` (now a short hand-written header), `dispatch_gl`, `run_tex`, the `OP_gl*` numbering (command numbers are `CMD_*` only), the per-hook statistics, the `LL_VK_NO_INTERCEPT` markers.
- Plaza: same picture, 15.7k records/frame (scene dependent), main thread queue cost 0.81 ms/frame.

## F2.2a done: typed texture descriptions (2026-10-10)
- `llvkformat.h/.cpp`: the one decoder from the viewer's GL enum numbers: `Target` (dimension + cube face), `Transfer` (components + component type of client pixels), `Store` (how a texture stores its texels, one entry per distinct treatment), `Setting` (min/mag filter, wraps, compare mode/func, anisotropy, base/max level, swizzle), `Swizzle`, `Level` (what a level query asks for). `LLVkTex::*` and `LLVkTarget::readPixels` convert once at the entry point; records (`TexArgs`, `TexOp`, the params record, the slot dimension of `CMD_BIND_TEXTURE_UNIT`/`CMD_TEX_SLOTS`/`CMD_DRAW`) and the worker (`Tex`: `mDim`, `mStore`, typed `SamplerParams`, `Swizzle[4]`; `tex_*`, `edit_*`, `read_pixels`, `tex_get_image`, `tex_level_parameter`, `encode_to_gl`) carry no GL number for textures any more.
- Behaviour notes: storage formats the worker treats identically are one entry (RGBA16F/RGB16F, RGBA32F/RGB32F, the depth sizes), so re-specifying between them keeps the image; level queries no longer answer GL_TEXTURE_INTERNAL_FORMAT (nobody asked); `GL_GENERATE_MIPMAP` is ignored as before.
- Plaza: same picture, 14.1k records/frame (scene dependent), no warnings; a 4100x2178 snapshot (readPixels path) complete.

## F2.2 done: no GL enum or GL type in the worker (2026-10-10)
Commits 04b90e7c (F2.2a textures), 1fee932a (F2.2b geometry) and the one after this note (F2.2c plain integer types).
- F2.2b: `llvkformat.h` also decodes draw modes (`Topology`), vertex attribute and index component types (the `PType` values: `T_U8 ... T_F16`) and buffer kinds (`BufKind`: vertex, index, uniform, other). `LLVkAsync::drawRangeElements/drawArrays/setArrayState/bufferData` convert once; `CMD_DRAW`, `CMD_ARRAY_RUN` and `CMD_BUFFER_DATA` records carry the typed values. The worker's vertex input (`VaoAttrib`), `vertex_format`, `draw_arrays/draw_elements` and `on_bufferData` use them. Removed from the worker: the framebuffer draw/read buffer enum arrays (a target has a colour attachment count; reads come from colour attachment 0), `compare_op`/`blend_factor` (dead since F1.1), the GL query-parameter numbers (`own_query_value` takes a bool).
- F2.2c: `llvkgl.cpp`, `llvkasync.cpp` and `llvkgl.h` use `U32/S32/S64/U64` where they had `GLuint/GLint/GLsizei/GLenum/GLsizeiptr/GLuint64`; the fallback `#define GL_*` block is gone. No `GL_*` constant and no GL type name is left in the worker or the records.
- Where GL numbers still exist, by design: the viewer-facing API (`LLImageGL`, `LLTexUnit`, `LLVertexBuffer` hold GL format/filter/type numbers and pass them to `LLVkTex`, `LLVkAsync`, `LLVkState`), decoded once at those entry points (`llvkformat.cpp`, `llvkstate.cpp`).
- Plaza (3 runs, same picture, no warnings, 14.1-14.7k records/frame) and the 4100x2178 snapshot after F2.2a and F2.2c.
