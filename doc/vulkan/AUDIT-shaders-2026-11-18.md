# Audit: the native shaders and the program system (2026-11-18)

Asked by Adam: "another audit for the shaders since those were all made native. see if there's any obvious wins there and report", then "let's cover the uncovered except for smaa".

Method: reading only. Nothing was edited, built, run or measured. Six read-only studies: the lighting and post chain; the geometry passes; ray tracing, the three very large shaders and the compute shaders; the program system on the C++ side; water, terrain, impostors, UI and the small programs; the loop-built program families. The claims marked **(C)** were checked again in the source or the newest log after the studies came back; the others are a study's reading (V = the study read both the shader and its driver, U = inference). Per-frame counts and compile times are from existing logs (`<work>\run-logs\rf-def1.log`, `k21-def1.log`), GPU costs from the docs.

Tree: the first four studies read 826ac03c67, the last two f970f6af11. Between the two only `pipeline.cpp` and `llvkworker.cpp` changed among the files named here (no shader file, not `llvknative.cpp`, `llvkrenderer.cpp`, `llshaderprogram.cpp`, `llviewershadermgr.cpp` or the pools), so line numbers in those two files from sections 2 to 5 may be off by some lines.

Paths: `N/` = `indra/newview/app_settings/shaders/native/`, `P` = `indra/newview/pipeline.cpp`, others under `indra/`.

Scale: the whole lighting family is about 1 ms of a 6 ms GPU frame and a pass begin with its clear 0.01 to 0.02 ms, so no per-pixel item below is worth more than about 0.1 ms alone. The larger items are the hitches and the per-record uploads of section 1.

## 1. The program system

### Hitches and startup

1. **The pipeline cache is 221 MB and is written again on the render thread in every run (C).** `k21-def1.log:1259`: "pipeline cache saved: 226688 KB (458 pipelines built since the last save)", and the next line "worker command 1001 took 191.006 ms" (rf-def1: 185 ms, the only slow command of that log). Pre-warm builds served from the cache still add to `mPipelinesSinceSave` (`llrender/llvkrenderer.cpp:1099`), and `beginFrame` saves after 18,000 frames when the count is not zero (`:2217`). The loader ignores a file of 256 MB or more (`:1553`): 35 MB more and every start is cold without a word. Change: pre-warm hits do not count (or no save when the data size is unchanged), the write on a background thread, the cache dropped when the shader set changes. U: that the save is the whole of the 191 ms.
2. **No SPIR-V cache on disk; `GAINS.md` still says there is one (V).** The cache of f80b50747c went out with the stock translator (f64a161a20). Every start and every `setShaders()` compiles 196 programs with the linked glslang on the render thread through `syncCall`, the main thread blocked (`llrender/llshaderprogram.cpp:1440-1476`): 719 to 746 ms a run. Change: a cache of SPIR-V and reflection keyed on the files and defines.
3. **Any shader setting compiles everything again (V).** `handleSetShaderChanged` to `setShaders()`: all programs unloaded, 196 compiled, the render buffers made again. `RenderGlow`, `RenderAvatarCloth`, `RenderMaxTextureIndex` change no define. The global defines go in front of every program (`llshaderprogram.cpp:1457`).
4. **The shipped pre-warm list is stale (C for the old names).** `newview/app_settings/vk_pipeline_variants_default.txt` (238 lines, from 7 November): 72 lines (57 names) are programs that no longer exist (16 lines of "MultiLight Shader N" **(C)**); 81 of the 194 programs the log names have no line (Water Pull, Underwater Pull, Deferred Tree Pull, Deferred MultiLight, Water Haze Pull, Deferred Shadow Cube, the HUD pull programs). On a machine without a list of its own those pipelines are built at the first draw and that draw is dropped (`llvkrenderer.cpp:330`, `:1132`).
5. **About 246 of the 746 ms of compile are programs a default run cannot use (V).** See section 6.

### Per frame, on the CPU

6. **The override swap is gone at run time (V).** All 241 manifest lines build native directly (`llshaderprogram.cpp:886-913`); `draw_context_apply` (`llrender/llvkworker.cpp:3065`) and `NativeDrawSwap` (`:3034`) cost one false branch each; `nativeOverride` and `adoptFrom` never run. The front end per frame in rf-def1: 507 `bind()` 0.11 ms; 8,389 `uniform*` calls 0.17 ms (3,222 changed a value); 937 `uniformMatrix*` 0.04 ms; queue writing 0.22 ms. The main thread's uniform path is by location.
7. **The record's table addresses are in the per-pass block, so every record uploads the block again (C for the layout).** `N/alpha_pass.inc:10-15` puts `ll_packet_table`, `ll_packet_models`, `ll_packet_texmats` (24 bytes) in `LLLooseUniforms` (binding 0); `sky_pass.inc`, `water_pass.inc`, `avatar_shadow.inc` the same. Log: 840 ring copies and 417 KB a frame, 491 of them equal to an earlier copy of the frame; worst Deferred Alpha Uber Material Pull (39 copies of 4.1 KB) and Deferred Avatar Alpha pull (36 of 2.5 KB). Change: the `ll_packet_*` members in `LLLooseDraw` (binding 5) or a push constant. The ring itself is clean (a dirty flag per class, dynamic offsets, one descriptor set).
8. **The worker sets record uniforms by `std::string` name (V code, U cost).** About 38 sites of the form `program->hasUniform("ll_packet_table")` / `setInts("ll_packet_models", ...)` (`llvkworker.cpp:5292, 5421-5427, 5691-5718, 5922, 7386, 7870, 12506`): a string built and hashed into `mUniformIndex` each time; 172 such writes a frame for one name on one program in the log. `Program::packetUniforms()` (`llvkrenderer.cpp:684`) caches these indices and is used at four sites.
9. **The debug key file is polled in a normal run (C).** `debug_key` (`llrender/llvknative.cpp:416`) caches per key, so each key reads the whole of `<work>/rt-debug.txt` again every 500 ms; `LLVkBridge::nativeKey` is asked for 9 keys from the main thread (`P:2296, 15617, 23502, 23509, 23719, 24026, 24420, 24421`), with a mutex and a string hash a call. Four more pollers of the same path: `llvkrt.cpp:359`, `llvkworker.cpp:5187`, `:12306`, `P:14658`. Change: one reader, one parse per 500 ms, off unless an environment variable is set.
10. **`bindDeferredShader` for the 24 material G-buffer passes sets nothing the programs read (V).** `newview/lldrawpoolmaterials.cpp:147` **(C the call)**. The native programs (`gbuffer.vert` + `gbuffer_material.frag`) have 30 uniforms and 0 texture slots: every `enableTexture` returns -1, every uniform it sets is absent (shadow matrices, clip, bias, SSAO, screen size, sun and moon direction, SSR, probe LOD); `sunlight_color` and `moonlight_color` are in the block and no gbuffer file reads them; `bindReflectionProbes` binds nothing. The plain bind is `pull->bind();` as in `lldrawpoolsimple.cpp:113-119`. The bind also runs for empty passes. Not measured (the zone "materials: bind pull program" has it).

The `native_<family>` gate and the file watcher are inside the unreachable `nativeOverride`: hot reload does not exist any more.

The 24 `getenv` sites are all inside `setShaders`.
- **`llshaderprogram.cpp` / `llshadermgr.cpp`, about 300 lines (V unless marked):** `hash()` and `mShaderHash`; `uniformValueChanged` always returns true (26 call sites); `shouldChange`; `mValue`; the shader level retry in `createShader` (`:947`); `OLD_SELECT`; `mUsingBinaryProgram`; `gShaderConsts` / `addConstant`; the diffuseMap ordering block of `mapUniforms` (`:1308-1417`, U); 41 of the 281 reserved uniform names are declared by no shader; `clearShaderCache` removes a GL era directory.
- **Stale docs:** `NATIVE-SHADERS.md` lines 10 and 13-15 and the header of `alpha_pass.inc` describe the override swap and the hot reload as live; the doc gives the budget as 20,000 words, the code 40,000 (`llvknative.cpp:403` **(C)**).

Clean: no orphan shader file, no unused lib file, no missing manifest file, no unused manifest define; `llglslshader.*` is gone.

## 2. Lighting and post (default on unless said)

1. **Two full-screen depth copies a frame exist only so the haze can sample depth.** `N/copydepth.frag` **(C)**: copies the depth into `mWaterDis` by a `gl_FragDepth` write and also samples the RGBA16F colour although the colour mask is off (a tap the compiler cannot remove). Drivers `P:24492-24516` (`doAtmospherics`), `P:24557-24580` (`doWaterHaze`), also for every probe face, and outside the "haze" GPU zone, so the 0.06 ms haze figure does not hold them. Change: both hazes under a `DepthReadOnlyScope` sampling the attached depth, as the resolve and the local lights do (`P:23401`, `P:24012`); neither haze writes depth. At least: a depth-only copy without the colour tap. Picture: none.
2. **The last pass computes 24 `sin()` a pixel for a dither of 0.003 (C).** `N/post_nodof.frag:30-65`: 3 `noise()` of 4 `hash()` of 2 `sin`, at window resolution, unconditional (`P:22393-22417`). Change: one tap of the 128x128 noise texture (`mTrueNoiseMap`, used by `N/glow_extract.frag:45`) or an integer hash. Picture: the grain changes, needs an eye.
3. **The sky's per-frame constants are computed per pixel in every lit program (C).** `N/lib/atmos.glsl:20-24` (`exp` of the sun attenuation, two vec3 divides), `:42` (`pow(ambient, 0.9)`), `:64` (`srgb_to_linear(sunlit)`); the same in `N/lib/legacy.glsl:41-52, 95, 124`. All inputs are uniforms. About 9 pow or exp and 6 divides a pixel in the resolve and in every alpha program (`alpha_lit`, `alpha_pbr`, `avatar_alpha`, `lib/material.glsl`, `lib/shade*.glsl`, `water.frag`), so it grows with the alpha overdraw. Change: the attenuated sunlight (sRGB and linear), `blue_weight`, `haze_weight` and the ambient base as uniforms. Picture: none.
4. **The haze does its maths for sky pixels, then discards** (`N/haze.frag:61-74`, discard `:87`); the normal tap (`:63`) feeds `amblit`, which the haze does not use. Change: `if (depth >= 1.0) discard;` after the depth read, no normal read, `ll_view_pos` in place of the `inv_proj` multiply. Picture: none.
5. **A legacy pixel walks its probe list three times** (`N/resolve.frag:235, 241, 245`, each a `probe_mix`, `N/lib/probe.glsl:174-219`); the two reflection calls differ in LOD only, and `probe_reaches` does the box transform a fourth time. Change: one loop that makes the weight and the direction once. Picture: none; the taps are unchanged.
6. **The half resolution lightmap targets are RGBA16F for values in 0 to 1** (`P:1053`; `N/sun_lightmap.frag:189`), read by 2 x 13 blur taps and 4 upsample taps. RGBA8 halves the bytes; the full size `deferredLight` must stay 16F (it is the CAS scratch, `P:22232`). Needs an eye.
7. **The BRDF table is made again blindly** (512x512 RG16F, 1,024 samples a pixel) at the 200th, 400th and 800th `renderDeferredLighting` **(C)** (`P:23374-23381` at f970f6af11), because the first draw may be dropped while its pipeline builds. Three hitches of a few ms early in the session; a wait for the pipeline would make one.
8. **Only with the option on:** SSR always traces the full sample count (**(C)** `N/lib/ssr.glsl:267`: `max(count, count * rough * vignette)` is `count`); DoF does a `sin` and `cos` a tap, about 200 taps at the largest radius (`N/dof.frag:80-82`); FXAA has a full-screen bake pass only to put luma in alpha (`N/glow_fxaa.frag`, `P:21391-21411`) and `N/fxaa.frag:230` writes `gl_FragDepth` into a target without depth; with DoF, material blend draws in the depth-only alpha pass run the full lit material program with the colour masked (`lldrawpoolalpha.cpp:255`, `:1147`).
9. **Tiny:** `N/resolve.frag:52-53` reads depth and albedo before the sky early out; `N/cas.frag:2549` fetches the centre texel a tenth time.

`cas.frag` is 2,558 lines because it is generated (`make_cas.py`): AMD's `ffx_a.h` (lines 29-2041) and `ffx_cas.h` pasted whole; the live code is the 3x3 filter with 9 `texelFetch`. 19,536 words and 10 ms for each of two programs: compile time only.

Local lights today: point lights with the camera outside are one instanced draw of boxes; lights that hold the camera are full-screen draws of up to 16 lights with a reach bit mask; no clustering, and none needed at the 0.03 ms measured.

Tight already: the resolve's branches; `sun_lightmap.frag` (only the cascades a pixel is in, 5 taps each, 8 AO taps); blur and upsample; glow (skipped when nothing glows, 512 wide); luminance (256x256) and exposure (1x1); tonemap; motion vectors; the radiance and irradiance filters.

## 3. Geometry passes

1. **Opaque glTF shadow casters go through the alpha test caster program (C).** `P:19178-19181` tags every opaque glTF caster `ALPHA_OPAQUE` into the 80 byte alpha record; `N/shadow_alpha.frag:17-20` returns early for the flag, but the stage has `discard` further down and `N/shadow_alpha.vert` carries five varyings and the texture window logic. So these casters lose the depth-only path in every cascade (the legacy opaque casters use `shadow.vert` on a depth-only target). Change: `GS_OPAQUE` entries to the opaque caster record (32 bytes, no varyings), or a fragment variant without discard. Picture: none. The value follows the glTF share of the scene.
2. **Every static G-buffer pixel carries two vec4 motion varyings to write a constant (C).** `N/gbuffer.vert:78-94` (and `alpha_pbr.vert:81-97`) loads a whole `mat4` a vertex (`motion_table.m[2*row.model+1]`) to test one flag; each fragment runs `ll_motion_encode`. `GB_MOTION=1` is on 33 manifest lines **(C)**, and the worker builds the motion table whenever the program has the uniform (`llvkworker.cpp:9412-9445`), with or without an upscaler; the camera matrices are set only with one (`P:20622-20643`). Change: (a) one varying (the previous clip position; the current one from `gl_FragCoord`), as `PLAN-velocity-fold-and-skin-once.md` line 91 suggests; (b) a "moves" bit in the row; (c) programs without `GB_MOTION` when there is no motion attachment. An A/B of the static manifest lines without the define would also settle the "pool: simple +0.5 ms" that plan never explained. Picture: none.
3. **The glTF ORM and emissive maps are sampled when the material has none (C).** `N/pbr_opaque.frag:66` (ORM) and `:75` (emissive and `srgb_to_linear`), the same in `alpha_pbr.frag:65, 68`; the driver puts the white image in for a missing map (`P:9468-9469`, `:10013-10014`). Change: no emissive fetch when the flat `vary_emissive` is zero; no ORM fetch when the slot is the white image's. Picture: none.
4. **No opaque G-buffer program is free of `discard`; glTF opaque and mask share one program (V; bounded).** `mirror_clip` (`N/lib/clip.glsl:4-10`) is a discard under a uniform test in `gbuffer_diffuse.frag:36`, `gbuffer_material.frag:46`, `gbuffer_bump.frag:40`, `pbr_opaque.frag:45`; `pbr_opaque.frag:50` and `gbuffer_bump.frag:43` also discard by cutoff on opaque draws. Change: the mirror clip as a clip distance in the vertex stage, and a `PBR_MASK` define. Upper bound: the measured overshading, 25 percent of the static fill, 0.05 ms at home (`SHADERS-F3-gbuffer.md` 7.2).
5. **Static opaque draws are not ordered front to back** (`llvkworker.cpp:9158-9166`: listed order per type). A sort of `listed` by distance adds no GPU work; needs a position per fragment on the worker. Same bound as 4.
6. **Lit particles take the full per pixel lit path** (`N/alpha.vert:54-61`, `alpha_lit.frag:70`: 5 PCF taps a cascade, the probe gather, up to 64 lights). Per vertex lighting for particle rows needs an eye; only worth it where particles are many.

Tight already: indexed draws where they measured better; skinning (skin once was measured and rejected; the previous pose is skipped for still palettes and without an upscaler); no `inverse` or `transpose` in the tree; the shadow vertex stage reads positions only; 4 cascades, depth-only, GPU cull and compacted indirect draws, the far ones on an interval; the legacy opaque, mask and material variants are chosen by manifest defines; the alpha pass takes its shadow after the alpha discard; the one geometry shader is a debug view. The row is 160 bytes, the model block 176; `skinPad2` has no reader.

## 4. Water, clouds, terrain, impostors, UI

1. **Water takes the sun shadow for every pixel and only the glint uses it (C).** `N/water.frag:155` `sun_shadow` (5 PCF taps, 10 in an overlap); its one use is `punctual` at `:212`. With SSR off (the default) those taps are about half of the water's texture reads; water was 0.63 to 0.82 ms in GAINS. Change: the lobe first (`:206-211`), the shadow only where the glint is above about 1/1024. Needs an eye (not exactly equal: `nl` is clamped to 0.001). `sunlit` is the per pixel constant of section 2 item 3 here too.
2. **Clouds: 14 noise taps a cloud pixel, 7 of them of a texture with weight 0 (C).** `N/clouds.frag:26-32` always reads `cloud_noise_texture_next` and mixes by `blend_factor`, which the driver sets to 0 with one noise texture or no scroll (`newview/lldrawpoolwlsky.cpp:318-336`). Change: the second read only when `blend_factor > 0` (as `water.frag:66` does), and no disturbance lookups (8 taps) when `cloud_variance == 0`. Picture: none.
3. **PBR terrain fetches the emissive texture when the emissive colour is zero (C).** `N/pbrterrain.frag:165` for every used material and triplanar slice, multiplied by `emissiveColors[m]` at `:292`; the colour is black for almost every terrain material. 1 of 4 fetches a sample. Also `terrain_uv` (`:175-187`) makes sin, cos and three mat3 a call, 5 calls a slice: a 2x3 matrix per material from the CPU would replace it. Picture: none. Only on regions with PBR terrain.
4. **The water exclusion mask is a screen size pass in every view, nearly always all ones (C for the missing gate).** `doWaterExclusionMask` (`P:24629-24640` at f970f6af11): a pass begin, a clear and all water planes plus the invisible draws, in the main view, the HUD view (nothing reads it), twice per impostor update, per probe face. Change: not for `sRenderingHUDs` or `sImpostorRender`; in the main view a white texture when the frame has no invisible draws. Picture: none.
5. **The water's screen copy and the haze's depth copy run with no water in view (C for the gate).** `LLDrawPoolWater::getNumPostDeferredPasses` is 1 whenever the camera is below 1,024 m (`newview/lldrawpoolwater.cpp:100`); `beginPostDeferredPass` then copies colour and depth full screen into `mWaterDis`; `doWaterHaze` copies the depth again and draws nothing above water. Change: skip both when the water pool's `mDrawFace` is empty and the camera is above water. With water in view there are three full-screen copies into `mWaterDis` a frame; not established whether one is redundant.
6. **Opaque water: the above water haze pass is overwritten in full** (only with `RenderTransparentWater` off, so not the default): `water.frag:108-112, 170` writes the fog colour over the same pixels with blend off.
7. **Impostors (not a proposal):** an update is a G-buffer fill, the post-deferred walk twice (the second depth-only) and a mask quad, into a target of at most 512x512; no lighting resolve; updates follow changes (angle, 10 percent distance, 5 cm extents) with no cap a frame; 2,740 images over 36,000 frames in the log. Only the mask passes of item 4 are free.

Answers: the Water Pull program's fragment stage is 23,521 words (probe mixer, four cascades, the PBR lobe, atmos, the legacy lib and three SSR marchers of which a session uses one); its 60 ms is the first compile of the run and likely holds the compiler's warm-up. The 20 PBR terrain lines are 2 programs (paint type 0 or 1); which terrain program draws is the region's choice (`lldrawpoolterrain.cpp:282-299`), the paint map only through the local debug bake; the terrain bake runs from the menu, never per frame. The UI: about 360 draws and 350 KB of records a frame, drawn straight into the window after the upscale, one draw per cached string; its fragment shaders are a texture times a colour.

Possible bug, U: `lldrawpoolterrain.cpp:295` clamps `paint_type` to `TERRAIN_PAINT_TYPE_COUNT` inclusive, then indexes an array of that size.

Tight already: the sky draws after the opaque geometry; the terrain draws after the opaque prim pools; terrain fetches only layers with weight; the water's wave maps (3 taps, 6 while blending); the RLVa sphere, the probe display, the HUD view are bound only when used; the UI record cache is live.

## 5. Ray tracing (off by default: `FSVkRayTracing=0`, `FSVkMirrorQuality=0`)

1. **Every probe face's lighting pass makes a full scene call (C for the missing gate).** `P:23457-23469` calls `rtScene` with no `gCubeSnapshot` gate; each call builds the top level structure from nothing (`llrender/llvkrt.cpp:5031-5077`, about 12,000 instances). TLAS 0.32 ms a call (`PLAN-async-compute.md`); the extra probe calls about 1.9 ms a frame (`NEXT-glossy-mirror-fps-ab.md`, open there). Change: a probe face call that writes its header only and uses the main view's structure. Needs an eye.
2. **The reflection ray decodes a whole surface for every masked candidate and uses its alpha** (`N/rt_reflection.frag:2254-2311` calls `rtShadeSurface` up to 64 times a ray; the hit is decoded again in `rtResolveHit`). Change: an alpha-only decode like `rtAlphaCover` (`:1562`). Picture: none.
3. **Shadow rays from traced hits find the closest hit when any hit is enough (C for the flag).** `rtShadowRayHit` to `rtShadowRaySoftS` with `gl_RayFlagsNoneEXT` (`N/lib/rt.glsl:351`, the copy in `rt_reflection.frag:1780`); callers: the sun at each hit and up to 8 local lights. Change: `gl_RayFlagsTerminateOnFirstHitEXT` for these callers only (the sun lightmap must keep the closest hit for the penumbra). Picture: none.
4. **The pixel's own probe sample runs before every trace and is rarely used** (`rt_reflection.frag:4813-4829`; read only at `:4674-4680`).
5. **The traced reflection pass also runs for probe faces** (`P:23819-23822`, U for the reason).
6. **Two full-screen copies in the shadow chain:** the blocker copy every frame (`P:23570-23591`) and, with the upscaler, the lightmap copy (`P:23652`).

Size only, no GPU time: `rt_reflection.frag` is 58,371 words, over the budget; it is the frozen stock text with its own copy of `lib/rt.glsl` (1452-2656), SSR, the cascade and spot shadow code, probe debug code and water fog inlined. `gltf_scene.*` are the 16 glTF scene programs, built only with `GLTFEnabled` (off).

Tight already: one ray a pixel for the sun with early outs; hard rays stop at the first hit; opaque geometry never enters the candidate loop; instance masks by class; static structures refit or rebuild on change only; avatar structures on a period by distance.

Compute shaders (all GLSL strings in the C++, compiled at first use): the resident cull and the alpha cull (once per shadow pass, the table's high-water mark); Hi-Z downsample and box test (once a frame, the read back does not block); the particle sort; RT skinning (RT only). **The particle sort always sorts 1,024 slots**: all 55 bitonic stages for every store each frame (`llvkworker.cpp:11957-11987`), groups average 34 to 96 particles; the next power of two at or above `n` is enough. There is no exposure histogram, DLSS or FSR compute shader in the tree.

1. **Six alpha programs can never be bound (38.3 ms; C for the selector).** Deferred Alpha Pull, Alpha Uber Pull, Fullbright Alpha Pull, each and Skin. Every key passes `run_key` (`newview/lldrawpoolalpha.cpp:779-793`), which folds fullbright and material blend into key 0 in the world colour pass and maps 0 to 1 in the depth-only and HUD passes; `mat_ctx == uber_ctx`. 2. **Material Pull 1/5/9/13 and their Skin forms are the uber material program compiled eight more times (88.8 ms).** The same files, defines and word counts (36,942 / 36,242); 16 pre-warm lines too. Bound only for material blend draws in an impostor render or a depth-only alpha pass. U: the C++ `mFeatures` of the two were not compared.
3. **"Deferred Tonemap Legacy Gamma Post Process" cannot be reached (C).** `P:20295-20304` (f970f6af11): `legacy_gamma` and `no_post` both follow probe ambiance == 0, so legacy always takes the NoPost program.
4. **A lazy build has no working path today.** Everything goes through `setShaders`; the AA, CAS, denoiser, rim lift and RT sites already test `isComplete()`, so they bear a missing program. A compile cache keyed on the files and defines takes item 2's cost away without touching the selectors, and most of the rest.

The probe uniform block (49,248 bytes): the shaders read every member; `refBox`, `refSphere`, `refBucket`, `heroBox`, `heroSphere` depend on the view, `refParams`, `refIndex`, `refNeighbor` do not: so once per view, not once per frame; a used prefix needs five sub-ranges because the arrays are stored member by member. The second hero probe update the thread audit listed is fixed in the tree (`P:15601-15604`: only when the probes are off).
