## 2. Item A: rigged cascade casters from simplified index lists (GPU)
Goal: the rigged casters of the sun cascades draw a simplified index list, error at most about one shadow texel. Expected GPU 0.6-0.7 ms at best (dry run: 5-11 % of the triangles left at 1-16 cm, positions only; weights, UV seams and the real texel sizes will keep more). Worker CPU does not change (same draw count).
Design:
- Vertices, skin weights and palettes stay as they are; only the index list changes, so the skinning is untouched. meshoptimizer 1.0 is in the tree (`meshopt_simplifyWithAttributes`, absolute error option, vertex lock): use it with the bind-pose positions, the skin weights as attributes (so vertices that bend differently are not merged), normals and UV (seams), and the draw's border locked.
- Computed once per rigged draw and tolerance level on a pool thread, never on the main thread or the worker (the diagnostic laps showed what main-thread work does to the GPU chart). Until the result is ready the original list is drawn.
- Held as a small index-only buffer per draw and level; the cascade entry (`ShadowSkinEntry`) names that buffer, first index 0 and the new count. Worker and shaders unchanged.
- Level per cascade from the real texel size: shadow target size and the cascade's frustum extent (read from the viewer, not my guess of 2 mm / 1.5 cm / 5 cm / 10 cm). Cascade 0 stays full.
Risks: (1) **stale lists**: a draw whose vertex buffer is rewritten in place (LOD change, rebuild) must invalidate its cached lists, otherwise the shadow shows spikes; key by buffer, offset, count AND a fingerprint, and test with LOD changes. (2) mesh units are not always metres: use the absolute error in the mesh's own units via the skin's bind shape scale, or fall back to relative error. (3) the look: shadows of attachments at one texel of error should not change visibly; Adam judges by eye, with a `shadowlod=0|1` live switch for an A/B in one lap.
Gates: G1 shadows identical to the eye, a still difference view; G2 GPU frame in the stills down by at least 0.3 ms in a same-lap A/B (live key); G3 no validation messages; G4 an LOD change of an attachment and a teleport do not show spikes.

## 4c. What kind 29 is (measured 2026-11-04, lap on the new defaults)
Kind 29 is NOT the static table draw: it is the **alpha run** record (S5a, lldrawpoolalpha.cpp:799). One record per run of consecutive plan segments with the same key (program, blend function, double sided, rigged), so the records are the key changes of the back-to-front order: about 394 per submit, 788 a frame, 2.4 draws each, 3.5 us each = about 2.8 ms of worker a frame (SCENE_TIMES: ranges and copy 0.58, uniforms 0.36, prepare_draw and vertex input 0.31, stamp 0.18, draw call 1.46 us). The records cannot be merged without breaking the blend order. The static table draws (kind 22, 20 calls) are only about 0.3 ms a frame. Kind 21 (prepare, 0.97 ms a frame) is 0.67 ms of command copy and 0.19 of listing. So item D as first written (the scene table's static draws) is small; **the worker's real cost is the renderer's per-draw state application**: from the phases log, apply: uniforms 0.74, texture layouts 0.51, pipeline 0.44, sampler slots and ray scene set 0.42, begin pass 0.30, dynamic state 0.21, vertex input 0.13 ms a frame (about 2.9 ms) plus draw record 0.93 ms, about 38,000 draws a frame through it. Next: measure how much of that is redundant (state unchanged since the last draw) and cut it, since it serves every pass.

## 4h. The two smaller things: why 10% of the alpha casters are not resident, and what D2 would give (2026-11-04, late)

**Residency.** Diagnostic (rt-debug-free, always on in the VkScene log: 'why not resident'): of about 960 builder alpha entries per cascade pass, about 100 (10%) stay with the worker, and ALL of them are fragments whose model matrix is not a region's (rigid mesh attachments and other moving objects): a resident fragment needs a region matrix slot, a fixed bounding sphere and fixed rows. No fallback draws, no bounds failures, no unknown buffers. Ceiling of the gain: kind 1 is 0.119 ms a submit (0.24 ms a frame of worker) for those 250 entries; the GPU cost is the same either way. Making them resident means sending the moving matrices of every attachment fragment in range of the cascades each frame (not just the main view's) and transforming the sphere on the worker; a stale matrix would show as a wrong shadow of an attachment. Judged not worth it for 0.24 ms; parked.

**D2.** Kind 29 is 269 records a submit at 4.18 us (1.125 ms; with the phase/zone timers on, of the 3.5 us a record 0.18 is stamp+flight, 0.58 ranges and copy, 0.37 ranges loop, 0.36 uniforms, 0.31 prepare_draw+vertex input: none of it is the program change itself, so the cost is per record). The remaining program changes after D1 are mostly lit <-> material 13 (normal + spec map) and lit <-> material 5 (spec map), static and rigged. Fewer records by folding them into the merged program: about 150 of 269 a submit, so about 0.6-0.7 ms a frame of worker (D1 delivered 47% of its predicted saving; the plan's 2.3 ms was too high). The work: materialF (blend path, 445 lines, its own lighting) and alphaF are different shaders; the merged program holds both paths behind row flags (normal map / specular map), with the vertex side from materialPullV. Risk: register pressure on the GPU (A/B as for D1) and a bigger shader to keep identical in output.

## 4i. The static alpha fragment shader: the probe call (2026-11-04, late)

Diagnostic (a uniform alphadbg switched parts of alphaF.glsl off, one lap, 15 s steps, no zone timers: the zone timers load the main thread and drop the GPU to 50%, never use them for an A/B): static alpha runs 0.81-1.09 ms; without the sun shadow, the atmospherics or the 7 local lights no change; without the whole probe call 0.35 ms; with only the probe list (preProbeSample) or the list plus sampleProbeAmbient also 0.35 ms. So the cost was the rest of sampleReflectionProbesLegacy: the hero probe taps and the screen space reflection march it makes for a transparent surface whatever the glossiness, results alphaF never reads (it only uses the ambient term).

Fix: alphaF.glsl calls preProbeSample + sampleProbeAmbient itself (classic mode 0 only; classic mode leaves the ambient term at amblit, as the legacy call does): the same value, no picture change. Lap after the change: static alpha runs 0.34 ms (was 0.8-1.1), rigged alpha runs 0.47 (was 0.55), GPU utilisation fell to about 79% (the GPU is no longer the limit at this spot). The probe-list end bound I tried first (refBucket.y, loop to the last probe that reaches the bucket) changed nothing and was removed. The materials blend variants (materialF.glsl) use the gloss and legacy terms, so they keep the full call; PBR alpha (pbralphaF.glsl) not looked at.

SSAO taps (aoUtil.glsl, uniform ao_samples, rt-debug.txt aosamples=4/8, RK_VK_AOSAMPLES=4): 4 taps a frame, alternating halves, only with the upscaler's moving AO noise; default 8, built, not lapped (the lap that should have measured it ended early).

## 4j. Lighting passes: what was wasteful (2026-11-04, late)

Switch-off diagnostics (one lap each, 15 s steps, no zone timers): sun lightmap pass: the two spot shadow lookups were 0.42 ms of the 1.46 ms full-screen group, the sun shadow 0.19, the AO 0.2 (4 instead of 8 AO taps changed nothing: removed); soften pass: 0.75 ms of which the probe lookup 0.2 (the G-buffer read and write floor 0.47), atmospherics 0.035. Fixes (all the same picture): the sun pass samples the spot shadow maps only for a projector light that has a shadow map (uniform spot_shadow_mask from mShadowSpotLight) and only for pixels inside that map's frustum (the spot light shader reads the value only inside its projector frustum), sky pixels (depth at the far plane) skip the lightmap work, the soften pass skips the atmospherics for sky and HDRI pixels, the probe list loop stops at the last probe that reaches the depth bucket (refBucket[].y, no measured gain, kept because the work was pure waste), the hero probe taps skip where their weight is 0, alphaF only asks for the ambient probe term. Lap: the full-screen group 1.34-1.46 -> 0.91 ms, GPU a frame 7.8-8.3 -> 7.6-7.7 ms, loop 9.8-9.9 ms (CPU limited: main thread and worker both at 100%).
