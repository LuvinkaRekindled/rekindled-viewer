# Rename: Linden prefix (LL / ll) to Rekindled prefix (RK / rk), 2026-11-18

Everything we wrote under a Linden Lab prefix now carries our own, so our code is told apart from Linden's at a glance. This file is the old-to-new table. Grep for the new names; the old ones appear only here, in `indra/llxml/rksettingsrename.h` (the settings migration) and in a few doc lines that quote a historical name.

## Rule

- **Ours** = a name that is in HEAD and in neither base tree: the Firestorm base `4ae31a7ad6` and the merged Firestorm release tip `4ac201fdc5`. Decided by token (a whole identifier, never a substring) over every tracked text file, not by prefix alone. So `LLVertexBuffer`, `LLPipeline`, `LLViewerTexture`, `ll_round` and every other Linden name stay.
- Prefix swap only, same length: `LL` -> `RK`, `ll` -> `rk`, `LL_` -> `RK_`, `ll_` -> `rk_`; the FS-prefixed things we wrote follow the same way (`FS` -> `RK`, `fs_` -> `rk_`, `gFS` -> `gRK`, `FS_` -> `RK_`).
- Header guards follow their file: `LL_LLVKASYNC_H` -> `RK_RKVKASYNC_H`.
- **Stays on purpose:** Linden and Firestorm names (including the settings Firestorm ships), the `<FS>` / `<FS:Name>` comment markers of Firestorm's own convention, AMD FidelityFX names (`FSR`, `fsr*`, `gFsr`, `FSR_JX`...), `doc/vulkan/upstream-watch/` (it is about the real Linden Lab and Firestorm: `ll_from`, `fs_from`, `FS_REMOTE`, `FS_TAG_GLOB`), the magic bytes `FSDC` of the decoded texture cache file format, and Linden/Firestorm shorthand in old notes (`LLGLS`, `LLGLTF`, `LLFlexibleObject`, `llspatial`, `llvo`, `llviewerfetchedtexture`, `lllistener_ds3d`, `llx`).

## Environment switches: clean break

`LL_VK_*` is `RK_VK_*` everywhere (`LL_VK_DIAG` -> `RK_VK_DIAG`, `LL_VK_PIN_MAIN` -> `RK_VK_PIN_MAIN`, ...), `LL_RTC_MEDIA_PLAYOUT` -> `RK_RTC_MEDIA_PLAYOUT`, and the FS_ switches: `FS_CPU_ZONES`, `FS_CPU_ZONES_CPU`, `FS_AVATAR_TIMERS`, `FS_DEV_SETTINGS`, `FS_NO_LIGHT_BOUNDS`, `FS_SHADOW_NO_RIGGED`, `FS_SHADOW_PACKETS_AB`, `FS_SHADOW_RIGGED_AB`, `FS_DEFERRED_PACKETS_AB`, `FS_SKIP_INSTALLER` (viewer_manifest.py) became `RK_*`. The code reads only the new names; an old name set in a shell does nothing. The launchers and lap scripts in <work> (outside git: h6-fixed.ps1, h0-chain.ps1, rt-run-pts.ps1, rt-defer-start.ps1 which strips `RK_VK_*`, build-run.bat, build-package.bat, run-viewer-*.bat, alist-read.py, native-check*.py and the other helpers) were changed in the same step. The one-shot `apply-*`, `edit_*`, `conv_*`, `commit-msg-*`, `f<N>-*` scripts and the notes in <work> are history and keep their old names.

## Settings: migration

The settings we added with an FS prefix are `RK...` settings. `indra/llxml/rksettingsrename.h` lists 71 old -> new names; `LLControlGroup::loadFromFile` reads a key of a USER settings file that is in the table as the new name (the new name wins when both are in the file), so a saved value carries over at the first start and the next save writes the new key only. Settings Adam had saved and that carried over in the check on 2026-11-18: `FSVkDLSS`, `FSVkDLSSQuality`, `FSVkMirrorQuality`, `FSVkNeuralRender`, `FSVkNeuralRenderMode`, `FSVkUpscaler`, `FSVulkanRenderer`, `FSImpostorMaxDistance`, `FSShadowFarCascadeMaxCameraMove`, `FSSkipStaticRiggedAttachmentUpdates`, `FSTextureUpdateDivisor`. `--set` on the command line takes the new names.
