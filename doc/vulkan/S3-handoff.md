## Where S0-S2 stand (all committed, default on via the setting `FSVkResidentScene`, restart needed)
- **S0** persistent bindless table, **S1** per-group retained fragments (`RKSceneFragment` in pipeline.cpp), RETAIN / RELEASE, `LL_VK_SCENE_VERIFY`.
- **S2** resident kind 0 shadow casters in a worker table (`ResGpu32` entries, bounds, models in `Memory::UploadDevice`, never read back by the CPU), GPU cull + indirect draw (`kCullShader`), the ray scene fed by residency (`LL_VK_SCENE_RAYRANGE`), TLAS instance rows by deltas (`LL_VK_RT_INSTDELTA`), resident alpha masked casters (`LL_VK_SCENE_RAYALPHA`, on again by Adam's choice after the stale-address fix d9995666), texture identity by events (`getTexId` / name events, pins for the alpha records: `LL_VK_RT_PINS`).
- Switches: `LL_VK_SCENE_RESIDENT`, `_RAYRANGE`, `_RAYALPHA`, `LL_VK_RT_INSTDELTA`, `LL_VK_RT_PINS`, `LL_VK_RT_STALECHECK` (safety net, every 16th scene call), `LL_VK_SCENE_EVDEDUPE`. An explicit env value (also 0) beats the setting.
- Gains so far are on the worker (shadowPackets + rtScene 3.3 ms against 4.5-5.0) and stability; the main thread gain of kind 0 alone was 0.2-0.3 ms. The plan's big wins (main thread -2 ms for renderGeomDeferred, worker draws -4k) are S3.

## What S3 is (plan): replace renderGeomDeferred and the deferred packets for static opaque and material passes
Entries get a material id and texture identity; one cull compute pass per view, indirect draws per pass, per-draw data pulled from the scene tables. Gate: pictures identical (compare against the old path, a burst of screenshots; judge by eye and say so), main thread -2 ms, worker draws about -4k.
First steps (not started): (1) read how the deferred packets are built today (search `render_deferred_packets` / `renderGeomDeferred` in pipeline.cpp, the packet record layouts in `rkvkbridge.h`, the worker's `drawPackets`), and list every per-draw value the three pull shaders read; (2) decide what an S3 entry carries beyond the 32 B shadow entry (material slots via pins? uniform data?) and what the fragment must be extended with; (3) build it behind a switch with a verify mode that compares the table's entries per group against the builder's, as S1/S2 did.

**G1 residual (3,212 / 1,528 draw infos "not in the fragments"):** `g2-v` with the owner map: every one has NO recorded owner (neither `postSort` of a listed cull result nor the shadow job pushed it) and the passes involved are tiny (1 or 16 draw infos in the whole pass): they are passes of other views (impostors / probes / snapshots) whose cull result never went through the collecting `postSort` (`mGeoGroups` empty). ## Status 2026-10-21 (S3 session, part 4): G3 + G4 built and measured (`LL_VK_SCENE_GEO=2`, off by default): the table path is event-driven, verified clean, and a smaller gain than the corrected gate
**Launcher for Adam:** `<work>\run-viewer-s3-geo.bat` (serving on, stale check on; a commented `LL_VK_SCENE_GEO_AB=20` alternates it every 20 s). Scripted runs: `<work>\run-logs\g3-*.log`, `g4-*.log`; helper `<work>\ab_zones.py <log> [skip s]` (zone / pacing / GPU averages by phase), batch scripts in the session scratchpad (`g4runs.ps1`: verify + on/off alternation with a picture 12 s after each flip).
**What G3 changed (worker `rkvkworker.cpp` "S3 G2 / G3", viewer `pipeline.cpp`):** fragments are named by a dense handle; nothing is looked at per entry per frame. A fragment is rebuilt only on an event: a buffer it reads got other storage (`Buf::mGeoWatched`, `sGeoChanged` by the write sites: causes epoch and moves), a buffer went (`geo_buffer_gone_impl`), a texture was named otherwise (kind 24 from the viewer's registry), or a pin of its textures got another slot (`sGeoPinEpoch`). Textures are PINS (`rtPinAcquire`: permanent bindless slots in every frame's set: removes the in-flight slot hazard of the write-combined single buffered table). The write path asks `geo_in_flight_impl` (the fragment's last listed frame) instead of the worker touching every buffer every frame. Viewer: postSort pushes `group->mGeoHandle` (a field of the group, hot in the loop) into `cull->mGeoHandles`; the texture identity registry (`sAlphaTex`, now indexed by the image id: `sTexById`, no scan) serves the geometry fragments too (`mGeoUsers`), a reconcile scan every 256 frames counts events that did not arrive (13 and 82 names of 2k-10k texture changes in the two alternation runs: harmless, healed, the safety net does its job); fragments are attached (RETAIN with names) when built, released at the end of the frame (handles reused after). Safety nets (on): worker stale check every 16th prepare (buffer addresses by fresh lookup, texture slots by the per-frame path, command lists): **0 stale in 563 + 488 + 300 runs over about 1.3M fragment looks**; viewer verify compares registry names with `prepareFast` (0 stale).
**What G4 changed:** `postSort` leaves the types a group's table fragment draws completely out of the render map (`LLSpatialGroup::mGeoServedMask / mGeoServedTris`, main view only, not while verifying), the triangle statistic is added per group; `LLDrawPoolMaterials` binds nothing for a rigged pass without draws and binds its own deferred shader only when the packets leave a draw (`LL_VK_POOL_LAZY=0` goes back); views other than the main one (probes, impostors) are never served.
**Verify (`g4-v`, London, 54.6k passes, 8.2M render map draw infos):** 0 not in the fragments (the G1 residual was the passes of other views, now skipped and counted), 0 extra, 0 builder differences, 0 fragment differences, 0 stale texture names, no device lost, no warnings from the table in any of the 3 + 4 runs.
**Pictures (alternation runs `g3-ab1/2`, `g4-ab1/2`, 8-9 shots each phase, taken 12-14 s after a flip):** the ON-vs-OFF mean difference is never above the ON-vs-ON / OFF-vs-OFF difference (sky and buildings 4.8-9.0 against 5.3-13; ground 0.9-6.3 against 0.9-13); judged by eye: right.
**Numbers (London, about 850 fragments / 1,630 entries / 13 draw records a frame, alternating 20 s phases, pure windows, runs `g4-ab1`, `g4-lz0`, `g4-ab2`):**
- *Worker, per frame:* old path = 9 table builds of 70 us + records = **0.68 ms**; table path = **0.26 ms** (prepare 0.19-0.21: pins 0.05, listing 0.07, stale check 0.04-0.046 (every 16th frame, averaged), command copy 0.035; draw records 0.035-0.057; retain 0.009; release 0.004). About **-0.4 ms** (-60 %). The stale check is 20 % of the table cost: it can go to every 64th now that it has found nothing.
- *Main thread, per frame:* `rk_scene_geo_frame` 1.1 us, retain at group rebuild 4 us, registry events + keep-alive 0.4 us + reconcile 0.6 ms every 256th frame; `renderGeomDeferred` 1.22 -> 1.06 (-0.16), `pool: simple` 0.15 -> 0.09 (-0.06), `pool: materials` 0.43 -> 0.38 (-0.05, of which the lazy binds about 0.035: 24 old-shader binds and 8.6 rigged passes skipped a frame), `packets: geometry` 0.15 -> 0, `postSort` 0.90-1.1 -> 0.87-0.93 (-0.03 to -0.22 between runs; the render map loop itself only -0.035: the pushes are not what it costs), `stateSort (early)` -0.02 to -0.25. **Total main thread about -0.2 to -0.4 ms; the corrected gate (0.8 ms) is NOT reached.** Frame interval ON 17.0 / 17.3 / 19.1 against OFF 18.0 / 17.3 / 19.2 ms (inside the noise of the windows).
- *GPU:* 8.00 ON against 7.95 off (g4-ab2), 7.80 against 7.75 (g3-ab2): equal within noise; the G-buffer pass did not get slower.
- *Draw counts:* the 1,630 entries are one indirect record per pass type (13 a frame) as before: the "-4k worker draws" of the plan was already taken by the packets (see the design note).
**Why the main thread gain is small (and what is left on it):** what remains of `renderGeomDeferred` (1.06 ms) is not the geometry any more: `pool: materials` 0.38 ms in 25 calls is the deferred shader setup of 12 passes (`bindDeferredShader` sets 100+ uniforms per program: 24k uniform calls a frame, 0.5 ms in the front end log), avatar 0.25, terrain 0.08, alpha mask 0.05, glTF 0.05. The next real main-thread step is therefore not more table work but the pass uniform block of the foundation design (uniforms by frequency: write the pass's lights / shadow maps / probes once per pass, not per program bind). `postSort` 0.9 and `stateSort (early)` 2.0 stay until the per-view lists are retired for all pass types (S4 / S5, "retire the per-view jobs").
**Not done / known:** (1) default stays off: Adam to use the launcher in a heavy sim; teleport and edit paths are not exercised by me (fragments rebuilt on edit are covered by the event machinery and the stale check, but never run by a person); (2) non-region (bridge / linkset) draws stay on the builder: 333 of 1,960 entries (17 %) of London's G entries: they need per-frame matrices (a moving-matrix table: S4); (3) a texture whose GL texture was deleted gets recreated by the registry round robin (at most 4 a frame, each texture visited about every 64 frames) instead of at its first draw: a short default-image flash is possible under memory pressure (not seen); (4) `LL_VK_SCENE_GEO=2` builds the fragment of every rebuilt group (4 us a frame) and keeps the registry (about 8k textures) alive; (5) the per-visible-fragment work left is the viewer's handle list in postSort and the worker's listing (0.07 ms).
