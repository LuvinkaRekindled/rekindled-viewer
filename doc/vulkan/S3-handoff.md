## What S3 is (plan): replace renderGeomDeferred and the deferred packets for static opaque and material passes
Entries get a material id and texture identity; one cull compute pass per view, indirect draws per pass, per-draw data pulled from the scene tables. Gate: pictures identical (compare against the old path, a burst of screenshots; judge by eye and say so), main thread -2 ms, worker draws about -4k.
First steps (not started): (1) read how the deferred packets are built today (search `render_deferred_packets` / `renderGeomDeferred` in pipeline.cpp, the packet record layouts in `llvkbridge.h`, the worker's `drawPackets`), and list every per-draw value the three pull shaders read; (2) decide what an S3 entry carries beyond the 32 B shadow entry (material slots via pins? uniform data?) and what the fragment must be extended with; (3) build it behind a switch with a verify mode that compares the table's entries per group against the builder's, as S1/S2 did.
