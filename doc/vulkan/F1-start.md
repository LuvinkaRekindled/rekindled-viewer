# F1: where to start (written 2026-10-10 at the end of the F0 session)

Read first: `PLAN-gpu-scene.md` (Foundation F), `F0-inventory.md`, memory `feedback-foundation-before-features`. Rule: every step is dual-write + verify beside the old stream, then the old calls for that family are removed; the viewer stays playable and the old path is the reference until F5.

## F1.1 the state family (first, smallest, cleanest)
**What the worker does today (verified by reading):** `llvkgl.cpp` 4238-4295: `on_glEnable/Disable` (`set_cap`: GL_BLEND, DEPTH_TEST, CULL_FACE, SCISSOR_TEST, STENCIL_TEST, POLYGON_OFFSET_FILL, DEPTH_CLAMP, others in a map), `on_glBlendFunc(Separate)`, `on_glDepthFunc/Mask`, `on_glColorMask`, `on_glCullFace`, `on_glPolygonOffset/Mode`, `on_glLineWidth`, `on_glViewport`, `on_glScissor` only store values in `sGL`. `on_glStencilFunc/Op/Mask` and `on_glPointSize` are **no-ops** (stencil test is forced off in `sync_draw_state`, "the mirror's depth images carry no stencil yet"). `sync_draw_state` (llvkgl.cpp 1276-1363) translates `sGL` into the Renderer's native `RasterState`, `DepthStencilState`, `BlendState`, viewport and scissor at draw time (skipped when a `DrawStateKey` compare shows nothing changed). Other readers of the same `sGL` fields: `on_glClear` (colour/depth mask, scissor), the `glGet*` answers (`own_glGetIntegerv`: BLEND_SRC_RGB, CULL_FACE ...), the sampler/feedback checks. Mapping helpers to reuse on the producer: `blend_factor()`, `compare_op()`, the cull/polygon mode switch in `sync_draw_state`; the front face is always `VK_FRONT_FACE_CLOCKWISE` (GL CCW with the positive viewport).
**Producers:** `LLGLState`/`LLGLEnable`/`LLGLDisable` (llgl.cpp), `LLRender` blend/depth/colour-mask/cull/scissor/polygon setters and `setSceneBlendType` (llrender.cpp), `LLRenderTarget` (viewport), plus stray `gGL`/`gl*` calls in pipeline.cpp, llspatialpartition.cpp, llviewerwindow.cpp, llmaniptranslate.cpp, llface.cpp.
**Design:** a plain `StateBlock` (native enums: Vulkan blend factors/ops/compare ops/cull mode/polygon mode, bools, depth bias values, line width, colour write mask, viewport, scissor+enable, stencil fields for later) in a producer-side `RenderContext` (`gRender`, no globals other than that instance). The setters above write the block fields (translation done once, on the producer, using the helpers listed). At a draw (or any record that depends on state) the context compares with the last emitted block and, when different, appends a typed `CMD_STATE` record holding the block (interning by hash is the step after: first just the 64-byte block). The worker handler copies the block into `Renderer` through the existing typed setters; `sync_draw_state` shrinks to "viewport/scissor against the current target". `own_glGet*` state answers come from the context.
**Steps:** (1) add `RenderContext` + `StateBlock` + `CMD_STATE`, dual-write from the existing hooks (the hooks stay, the context is filled by a function called next to them); (2) worker verify mode (env `LL_VK_STATE_VERIFY=1`): at every `sync_draw_state` compare the Renderer state built from `sGL` with the one the block would produce, log the first 30 mismatches; run the plaza + login + a snapshot; (3) once 0 mismatches over a long run, switch the callers (LLGLState, LLRender, LLRenderTarget, the stray calls) to call the context directly and stop enqueueing the 17 GL ops (count records per frame before/after: expect about 3.6k fewer per frame: glBlendFuncSeparate 1.3k, glEnable/Disable 300, glDepthMask 140, glScissor 190, glColorMask 55, glViewport 46, glCullFace ...); (4) add real stencil state (the no-op functions) if any pass needs it; (5) delete the 17 hooks from `gen_llvkgl.py` FUNCS and `on_gl*` handlers. Gate for each commit: same pictures (snapshot before/after in the same spot), records/frame down, frame time not up.

## F1.2 the rest, in this order (each the same dual-write/verify/switch/delete cycle)
textures and texture units (`glBindTexture`/`glActiveTexture`/params/uploads; the typed slot records already exist: `CMD_TEX_SLOTS`, `PendTex`) -> buffers and vertex arrays (`LLVertexBuffer`: `glBindBuffer/BufferData/SubData/VertexAttribPointer`, draws as typed draw records with buffer ids) -> render targets (`LLRenderTarget`: FBOs, `CMD_TARGET_STATE` and `CMD_FBO_ATTACH` already exist) -> programs and the uniform classes (the table in `uniform-classes.tsv`; `LLGLSLShader` setters, `CMD_UNIFORM_BATCH`, `CMD_SHADER_BIND` exist) -> queries/fences/readbacks (F4).
Handles: GL names are already allocated on the producer without a driver (`own_gen`), so they are the handle table in practice; the change is to stop carrying GL enums/semantics (bind points, active units, VAOs) and to wrap them as `TextureId`/`BufferId`/`TargetId`/`ProgramId` when the family is switched, not before.
