## What S1 is (from the plan, narrowed by the numbers)
"Scene tables and deltas for static opaque geometry: Entries / Instances / Materials filled from group rebuilds; a verify mode compares the scene's entry count and ranges per group against the old draw maps. No rendering change yet. Gate: 0 mismatches over a long run."
Suggested order for the session (each its own commit, build in the background, no polling, London only):
1. **Entries for one pass family from group rebuilds** (the retainable set: opaque, not rigged, no texture matrix): a fragment per group = the group's retainable infos as entries (vertex buffer id, index buffer id, first index, count, flags, material key), keyed by `mDrawMapSerial`; free it with the group; RETAIN / RELEASE in the ordered queue (the worker keeps the id -> entries table). Start where the packets already exist: shadow kind 0 (untextured static casters: `ShadowPacketEntry`, `render_shadow_packets` in `pipeline.cpp`, `lldrawpool.cpp pushGeometryPackets`), because no texture is involved (phase 1 of the retained records plan).
2. **Verify mode** (`RK_VK_SCENE_VERIFY=1`): at each use compare the fragment with a rebuild from the live draw maps (entry count, ranges, buffer ids) and count mismatches by cause; gate 0 over a long London run plus a teleport round trip (region change, group destruction) and an edit session (Adam does the edits).
3. Only then: use the fragment instead of the per-frame builders for the shadow packets (the S2 step) and measure the main thread zones (`RK_CPU_ZONES=1`: `renderShadow`, `packets: shadow static`, `generateSunShadow`) in London.
Invalidation list: see `PLAN-retained-records.md` (group rebuild, texture swap, vertex buffer reallocated without a rebuild, active / static change, region shift, group destroyed, cascade avatar cull, rigged alpha, impostors).

## Status 2026-10-20 (S1 steps 1-3): fragments + verify built; verify clean in London; using them is NOT faster yet
**Built (switches, both off by default; code in `pipeline.cpp` "S1" block, `llspatialpartition.h` `mSceneFragment`, worker kinds 11-13 in `rkvkworker.cpp` / `rkvkbridge.h`):**
- A fragment per spatial group = `ShadowPacketEntry`s of the 13 static types (shadow kind 0), local matrix list, fallback draws, the vertex / index buffer ids it saw. Valid while `mDrawMapSerial` is unchanged and those buffers still have the same ids (else rebuilt). Freed with the group; the worker keeps a copy by id (RETAIN kind 11, RELEASE kind 12, queued in the ordered stream; releases are collected under a lock and sent with the next pass). A pass names fragments (kind 13: ids + per-fragment matrix map + the pass's matrices) and the worker expands it into the same record as kind 0.
- `RK_VK_SCENE_FRAGMENTS=1`: the prepared sun cascades are drawn from fragments (not with ray-only shadows or ray materials: then the builder). `RK_VK_SCENE_VERIFY=1`: every fragment met is compared with a rebuild from the live draw maps (entry count, fallback draws, matrices, vertex / index buffer ids, ranges, matrix number / id) and each cascade's entries (as a sorted set with the matrix contents) and fallback draws with the builder's; log tag `VkScene`, "fragments (shadow kind 0)" every 600 frames. A buffer id changing under the same serial counts as a mismatch ("vertex buffer id") and the fragment is rebuilt.
- **To run it, ray shadows must be off:** with `RKVkRayTracing` the cascades are note-only (`rt_skip`) and never reach the fragments. The scripted run needs `RK_VK_RT_SHADOWS=0` in `RT_ENV` (`RT_OFF=1` alone does not stop the setting from turning them on). Manual launcher: `<work>\run-viewer-s1-verify.bat`.

**Verify result (London, scripted, `RK_VK_RT_SHADOWS=0;RK_VK_SCENE_VERIFY=1;RK_VK_SCENE_FRAGMENTS=1`, run `s1-verify6`, 9,463 cascade passes):** 14.4 M fragment checks, 0 mismatches in every cause, 0 buffer-id changes under the same serial, 9,462 cascade lists compared with the builder's: 0 differ in count, 0 in content, 0 in fallback draws; 38 k fragments built, 24 k retained, 20 k released, 0 fallback draws. Picture (`s1-verify6-b.png`, cascades drawn from fragments) judged by eye: tree and avatar shadows on the sand look right. **Not done: the teleport round trip and the edit session** (need Adam; the verify run is the launcher above).

**Main thread (London, `RK_CPU_ZONES=1`, `s1-base1` builder vs `s1-frag1` fragments, one run each, scripted runs vary about 1.4 ms):** `packets: shadow static` 0.18 ms (0.11 record + 0.07 wait for the builder job) -> 0.41 ms (the fragment collection runs on the main thread: about 1,500 group visits and a matrix lookup per fragment per cascade); `renderShadow` 1.02 -> 1.56 ms, `generateSunShadow` 2.46 -> 3.08 ms, loop 14.7 -> 15.5 ms. So replacing the builder by main-thread collection is slower: the builder already ran on the pool, and London is main-thread-bound. **The saving needs the per-cascade collection to go away, not to move:** do it in the pool job from fragments (the ensure step and fragment frees need a guard against the cascades' jobs), or phase 4 (group-level render maps, no per-view walks), or the S2 GPU cull reading the scene table. Fragments are the scene table's entries for S2 either way.
