# F3: the viewer's pass code onto the typed API (plan, 2026-10-19)

Part of `PLAN-gpu-scene.md` (Foundation F), after F2.7 (`F2-draw-records.md`). F2 made the **stream and the worker** typed: a draw is one record (program, vertex binding, texture ids, uniform ranges), state is a block, resources are ids. What is still GL-shaped is the **vocabulary the viewer's pass code speaks** and a few front-end mechanisms behind it. F3 moves that, pass family by pass family. Counts below are from the code today (2026-10-19).

## What is still GL-shaped (measured)
| What | Size | Where it shows | What it costs / why it goes |
|---|---|---|---|
| **Immediate mode** (`gGL.begin/vertex/texCoord/color/end/flush`, fixed-function style) | vertex 1,200 + texCoord 357 + color 341 + begin/end 380 call sites; 579 calls in `llrender2dutils.cpp`, 448 in `pipeline.cpp`, 237 `llspatialpartition`, 203 manipulators, 152 `llviewerdisplay`, 140 `llvoavatar` | `LLRender::flush` builds an `LLVertexBuffer` per flush (`genBuffer` / `bufferfromCache`, hash of the vertex data, `bufferSubData` records, pool names) and draws it like a mesh | the UI shader draws 612 per frame and `render_ui` is 1.2 ms of the main thread; a streaming vertex buffer per flush is a GL idiom (a Vulkan renderer writes into a per-frame ring) |
| **Matrix stack** (`push/popMatrix`, `loadMatrix`, `matrixMode`, `translate/scale/rotate`, UI matrices) | about 1,000 call sites | `LLRender::syncMatrices` writes modelview/projection/normal per draw | per-draw uniforms from a stack machine; the target is the draw class block (already a range write since F2.5) fed from values |
| **State by GL enum** (`LLGLState`/`LLGLEnable`/`LLGLDisable`/`LLGLDepthTest`: 426 sites; `GL_BLEND`, `GL_CULL_FACE`, `GL_FRONT_AND_BACK`, `GL_FILL/GL_LINE`, `GL_ALWAYS` ... in 600+ places; `setSceneBlendType` 52, `setColorMask` 89, `setPolygonMode` 63, `setLineWidth` 66) | scattered over `pipeline.cpp`, the draw pools, UI, manipulators | decoded once into the state block (`llvkstate.cpp`), and an `LLGLState` map of "what GL has" still exists on the producer | the enums are a translation layer; typed values are what the block holds |
| **Texture unit vocabulary** (`getTexUnit(n)->bind` 176, `bindManual` 39, `unbind` 196, `enable/disable` 42; `LLTexUnit::eTextureType`) | 114 files | a unit holds an id (F2.6); `unbind` writes id 0 | the 196 unbinds are bookkeeping for a table that no longer exists |
| **Render targets** (`LLRenderTarget`: `bindTarget/flush/clear`, `sCurFBO`, 18 files) | the passes' own structure | "bind FBO, draw, flush" | a target is images + load/store ops; this is where the frame graph (N2) starts; do last |
| **Vertex / index GL types** (`GL_UNSIGNED_SHORT`, `sGLMode`, `GL_FLOAT` attribute types in `LLVertexBuffer`) | the class itself | decoded in `llvkformat.cpp` | cosmetic: one table |
| **Readbacks, snapshots, media textures** | F4 | | |

## Order (each step: behind no switch, judged by pictures and counters; the old path is gone, so the reference is the build before the step)
**F3.0 reference set (before any step).** The old GL-shaped path no longer exists as a reference, so references are captured from the build that precedes each step: `<work>\rt-run-shot2.ps1` takes two pictures (40 s, 110 s) of a scripted spot; a compare script (`rt-shot-diff.py`, written in F3.0: per-pixel difference, count of pixels over a threshold, a difference image) judges a step. Spots needed beyond the London City crowd (named by Adam, started from the launcher with a SLURL, no GUI driving): water and underwater, an interior, night and dusk sky, a close avatar with hair, a HUD, a manipulator (edit mode screenshot needs Adam), a floater-heavy UI. Fixed environment (midday) like the existing runs. Noise rule: a step passes when the difference image is empty for static content and explainable (avatar/crowd movement) elsewhere.
**F3.1 immediate mode to a per-frame vertex scratch ring (first pass: the UI).** `LLRender::flush` stops creating `LLVertexBuffer`s: the vertices go into the producer's scratch (position / texcoord / colour for the bound shader's attribute mask), one record per flush carries them (`CMD_DRAW_SCRATCH`: mode, count, mask, the bytes inline like a buffer sub-data) and the worker writes them into `Renderer::allocVertexScratch` and draws non-indexed. Quads become triangles on the producer (as now). Gate: UI pictures identical (login screen, world with floaters, menus, nametags, HUD text, minimap), `bufferSubData`/`bufferData`/`bufferRecycle` records per frame down by the UI share (opstats), `FRONT END` counters for `flush`, `render_ui` main-thread ms (cpuzones launcher) not up. Then the same path serves manipulators, debug draws, nametags, text, selection outlines (all immediate mode). Expected: fewer records and no pool churn; main-thread gain unknown (measure first, the counters already exist).
**F3.2 state vocabulary, by pass family.** Typed setters next to the GL-named ones (`RenderState::setBlend(BlendMode::Alpha)`, `setDepth(...)`, `setCull(...)`, `setPolygon(...)`), the GL-named wrappers become thin and then are replaced file by file. Order: UI and immediate-mode users first (F3.1 touched them), then sky/atmospherics, terrain, water, the draw pools (simple, bump, materials, emissive, alpha, avatar), post (`llpostprocess`, DOF, tonemap), lighting, probes. Gate per file group: pictures of the matching scenes identical, record counts unchanged. At the end `LLGLState`, its map and `llglstates.h` GL constants are deleted.
**F3.3 matrices as values.** `syncMatrices` computes modelview / projection / normal from the producer's matrix values into the draw class block (done as a range write since F2.5); then the stack calls are replaced by passing matrices as arguments where a pass sets them once (cameras, shadow cascades, probe faces) and by a small transform stack local to the immediate-mode batch (`begin(transform)`) for UI and manipulators. Gate: pictures, `uniformMatrix*` ns per call (counter) down or equal.
**F3.4 texture unit cleanup.** `bind` stays as the API; `unbind(type)` and `disable/enable(type)` become no-ops documented as such, then their 238 call sites are removed pass by pass with F3.2 (a unit that is not rebound keeps its id: draws of other passes always bind what they sample: verified by F2.6's 28.7M-draw check). Gate: pictures; unit-id writes per frame down.
**F3.5 render targets as pass descriptions** (`LLRenderTarget` -> attachment list + clear/load/store; `bindTarget`/`flush` become begin/end pass). Feeds the frame graph (N2) and the removal of mid-frame layout transitions (179 per frame measured); last, because it changes pass structure, not vocabulary. Gate: pictures of every scene in the set, GPU zones (gpuzones launcher) per pass not up, barriers per frame down.
**F3.6 GL types in `LLVertexBuffer`/`LLImageGL`** become the typed enums of `llvkformat.h` (one table, callers keep working through constants until the end).

## Gates in one place
A step is done when: the build is clean; the reference scenes' difference images are empty or explained (two pictures per scene, early and late); the VkOps line shows no `unknown command`, records per frame equal or lower, worker ns per draw not up; the `FRONT END` counters of the touched entry points not up; the doc and the memory note are updated; the commit message says what was measured. Rule from 2026-10-19: compare against a reference picture of the same spot before calling a picture right, and when removing a record or a state kind grep the worker for every reader.

## Risks
- Immediate-mode users are everywhere (UI, manipulators, debug, name tags): a missed state assumption (texture unit, colour mask, scissor) shows as a wrong overlay; the pictures must include floaters, tooltips, selection outlines and the minimap. Manipulators and edit-mode overlays need Adam to enter edit mode (no GUI driving by me): list them as his items per step.
- No old path to A/B any more: the references are only as good as the scenes chosen; a bug outside the set is found by Adam in use. Keep the commit per step small so a revert is one commit.
- Main-thread gain is not the point of F3 (the front-end entry points measured 1.8 ms in total); the gain is a vocabulary the scene work (S1+) can build on, and fewer records and allocations. State that in each commit message with the measured numbers.

**F3.1 fix, same day (found by Adam with the bounding-box debug on):** every immediate-mode draw takes its vertices from the frame's vertex scratch, which was a fixed 8 MB ring shared with the packet tables: a debug draw of all bounding boxes (thousands of small flushes per frame) emptied it, `allocVertexScratch` returned null and every further draw of the frame was dropped (about 1.7 million refusals in 90 s in the log; the picture blinked, UI included). The old path (a vertex buffer per flush) had no per-frame limit. Fix: `Renderer::allocVertexScratch` continues in overflow chunks (32 MB each, up to 8 per frame slot, made when first needed, reused each time the slot comes round, released after 600 frames without use; `mVertexOverflow`). Adam's check with the same debug on: no flicker, UI intact, no "ring exhausted" in the log. LESSON: a fixed per-frame budget that an unbounded producer (debug draws) can exceed must grow or the draws must fall back; the crowd spot never showed it. The ring itself is unchanged for the other users (palettes, tables, indirect commands), which now also get the overflow instead of a dropped draw.
**Adam's checks of F3.1 (2026-10-19, build with the overflow fix):** bounding boxes on (28 fps, no flicker, UI intact), selection outlines, nametags, text, crosshairs (no jitter), world map, floaters: all fine. F3.1 is closed.

### F3.2b: the extra `state` records are the scene, not the migration (measured 2026-10-19, same crowd, same hour)
The gate "state records equal to the reference" was not met in absolute numbers (489-567 against 343-353). Cause found by A/B on the same machine within a few minutes, same crowd spot (79 people in range), `RT_NO_PHASES=1 RT_OPSTATS=1`: the F3.1 build (crash-symbols 20261019-175306, the build the references came from) gives **544-552** `state` records per frame (blendFunc calls 3431-3453, draws 5885-5948), the F3.2a build (20261019-183126) **556-559**, the F3.2b build **560-562**. Records per blendFunc call is not a stable measure across crowds (0.127 in the references, 0.158-0.172 today in all three builds).
What the records are (`LL_VK_STATE_WHY=1`, one 600-frame report in the log, `StateWhy`): of 335k `CMD_STATE` records per 600 frames (558 per frame), 247k change the blend function (writer: `direct setBlendFunc`, scene order of the passes), 42k depth write, 38k cull, 36k scissor rect (UI clip rects, 60 per frame, `direct setScissor`), 16k blend enable, 16k depth function, 15k viewport, 15k colour mask.
