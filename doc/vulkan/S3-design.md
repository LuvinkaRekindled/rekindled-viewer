# S3 design note (2026-10-21): the G-buffer from the scene tables

Status: DESIGN for Adam's review. No S3 code exists. Read with `S3-handoff.md`, `PLAN-gpu-scene.md` (S3), `S2-handoff.md` parts 1-14. Two things in it change the plan's S3 text (visibility and the gate): see "Decisions".

## 1. How the deferred packets work today (read from the code)
- **Which draws.** `LLDrawPoolSimple::renderDeferred` (PASS_SIMPLE, diffuse pull shader `diffusePullV.glsl`) and `LLDrawPoolMaterials::renderDeferred` (12 passes: material / spec / norm / normspec, each plain, mask and emissive; one pull program each, `materialPullV.glsl` with `HAS_NORMAL_MAP` / `HAS_SPECULAR_MAP` / `DIFFUSE_ALPHA_MODE` defines) when `FSDeferredPackets` is on. Everything else of the G-buffer stays on the old path: bump, fullbright, alpha mask, glTF, terrain, grass, trees, avatars (rigged), animesh, anything with a texture matrix.
- **Build (`lldrawpool.cpp`).** `kickGeometryBuilds()` at the top of `renderGeomDeferred` starts one job per pass on the async pool (13 per view); `build_geometry` walks the cull result's render map of the type (`LLCullResult::beginRenderMap`, built by `postSort` from the visible groups) and makes one `GeoEntry` per draw info: vertex / index buffer names, first index, count, offsets of normal / texcoord0 / colour (+ tangent, texcoord1, texcoord2 for maps), a model matrix number, up to four diffuse GL names (batched textures) or one, normal and specular map names, specular colour, environment intensity, alpha cutoff, brightness (fullbright). Per model matrix it computes `mv`, `mvp`, normal matrix (44 floats) for the view and projection of the pass. `pushGeometryPackets` waits for the job, `finish_geometry_build` calls `prepareFast` for every texture (setActive, regenerate a deleted GL texture, apply wrap / filter options, default image when there is no data), and sends the entries + matrices as one blob (kind 3). `geometry_packet_ok` sends to the old path ("fallback"): rigged, glTF, 32 bit indices, no position-first layout, texture matrix, more than four batch textures, missing arrays for the pass.
- **Worker (`on_geometry_packets`, rkvkworker.cpp:4140).** Per entry: two buffer lookups by name, buffer addresses, `packet_texture_slot` per texture name, a 128 byte `GeoGpu` into frame scratch; commands `{count, 1, 0, i}`; one `drawPackets` (one `vkCmdDrawIndirect`) per record. The matrices go to scratch (176 B each).
- **Per-draw values the three pull shaders read** (`GeoPacket`, 128 B): addresses of positions / normals / texcoord0 / colours / indices (+ tangents, texcoord1, texcoord2), first index, model matrix number, flags (one texture), four 16 bit diffuse slots, normal-map and specular-map slots, specular colour (vec4), environment intensity, alpha cutoff (mask passes), brightness (fullbright). Per matrix: `mv`, `mvp`, normal matrix. The vertex shaders pass the slots on as flat varyings; the fragment shaders (`diffuseIndexedF`, `materialF` with `RK_BINDLESS_*`) take them as inputs. **The fragments and the vertex shaders need no change for S3** if the table keeps this layout and the matrix table keeps `GeoMatrix`.

## 2. What the numbers say (London, current default build, `s14-default3/4`, `c1-async`)
- Main thread: `renderGeomDeferred` 1.13-1.15 ms in total; `pool: materials` 0.45, `pool: simple` 0.16, `packets: geometry (build + record)` 0.13 (0.85 in the older, heavier `c1-async` scene), `wait for the geometry builder` 0.1-0.35. Avatar 0.20, terrain 0.08, alpha mask 0.05, glTF 0.05 are not in S3's reach.
- Draw counts: `geometry packets per frame: 9 records, 1,940 draws in them, 4 left to the old path, ~200 matrices, ~1,530 textures bound`. The whole main deferred pass is ~1,080 old-path draws + those 9 records; the post-deferred (alpha etc.) is 3,266.
- **So the plan's gate was written before the packets existed and is mostly spent already**: "worker draws about -4k" counts entries that are already one indirect command per record (the draw counter adds the entries, `noteDraw(2, draws)`); the real remaining worker cost is the per-frame table build (1,940 x 128 B, ~3,800 buffer lookups, ~1,500 texture slot lookups, ~250 KB of scratch written and read by the GPU) and the blob copies through the queue. "Main thread -2 ms" is larger than the whole of `renderGeomDeferred`. What S3 can take off the main thread: the build kicks, waits and records (0.25-1.2 ms depending on the scene), the 1,500 `prepareFast` calls, the pools' bookkeeping for those passes (part of 0.6), and, if the render map stops carrying these types, a share of `postSort` (1.25 ms for 5.2 calls a frame, of which the visible-group loop is the part that scales with draw infos). Honest expectation: 0.8-1.5 ms main thread, plus the worker table build (to be measured: no timer exists for kind 3 yet).

## 3. What an S3 entry carries
The **same 128 B `GeoGpu`** the shaders read, kept in a persistent table (`Memory::UploadDevice`, write-only for the CPU like the S2 tables; the CPU keeps its own copy) instead of being rebuilt every frame. Differences from the shadow entry (32 B): array addresses are derived from the buffer address + the offsets, the material fields, and the texture slots. Slots are persistent: one table of 131,072 entries (16 MB) like S2, each fragment owning a slot list per pass type.
- **Model matrix:** only region matrices (static geometry), as in S2 (`all_region`); `model` = the region slot. Per frame the worker writes the `GeoMatrix` table for the used slots from `mMatrixCpu` and the view / projection of the record (256 slots at most, ~100 us); `rk_packet_models` points at it. Bridge / linkset groups and anything with a non-region matrix stay on the old path (S4).
- **Textures:** entry slots come from **pins** (permanent bindless slots kept by events, `rtPinAcquire`), via the same registry the alpha casters use (`sAlphaTex`: texture -> users, GL name changes as events, readiness): the G-buffer textures of a fragment are registered at fragment build, a name change or "now has data" event rewrites the slot fields of the users (kind 19 style update). `prepareFast`'s side effects are kept by a slow round robin `setActive` over the registered textures (as the alpha keep-alive does) plus one forced creation at registration; the default-image rule is kept (no data -> default image slot until the event). Cost to check: the pin count (all resident groups' textures, not only visible: thousands) against the bindless table size.
- **Material values** (`mSpecColor`, `mEnvIntensity`, `mAlphaMaskCutoff`, `mFullbright`) are properties of the draw info, so they change only when the group is rebuilt (the fragment is made again with the draw info set, `mDrawMapSerial`).
- **Fragment (viewer side):** `RKSceneFragment` gains, per pass type (13), the G entries `build_geometry` would make for the group's draw infos of that type (matrix = region slot, textures = indices into the registry, flags), the fallback draw infos of that group per type, and a "G-resident" flag (all draws region-matrix, no fallback needed for the group to be resident: fallback draws are allowed and listed). Sent to the worker like kind 14 (new kind, `RETAIN_GEO`); freed with the fragment.

## 4. Visibility and draw commands (decision 1)
The plan says "one cull compute pass per view". For the **main view** a frustum-only GPU cull would draw groups the CPU culled with **occlusion queries** (`OCCLUDED` state, `RenderAutoHideSurfaceAreaLimit`, the render-type toggles: the filters in the `postSort` visible-group loop) — more vertex and fragment work on a GPU that is busy 7.8 ms a frame, and not "identical to the old path" by construction. Proposal:
- **S3 uses the CPU group visibility the old path already computed.** The `postSort` visible-group loop (it iterates those groups anyway, the filters are there) appends the fragment id of every group that passes the filters to one list per view (a few hundred 4 byte ids), sent as one small record (`DRAW_GEO`: ids, view, projection). The worker keeps per fragment the slot lists per type, writes `VkDrawIndirectCommand`s ({count, 1, 0, slot}, 16 B each, ~2k a frame ~ 20 us) into one scratch range per pass type, computes the matrix table, and each of the 13 passes (`pushGeometryPackets` call sites) becomes `DRAW_GEO(type)`: bind of the pull program stays where it is, one `drawPackets`. No GPU cull needed for identical sets; the S2 cull shader stays as an alternative mode (`LL_VK_SCENE_GEO=2`: frustum compaction on the GPU) for the day Hi-Z exists (S7) and as an overdraw measurement.
- The old render map stays untouched in the first stage (verify compares against it); the second stage stops `postSort` from pushing the S3-covered draw infos of G-resident groups into the render map (only fallback ones), which is where `postSort` and the pool loops get cheaper.

## 5. Verify mode (as S1 / S2)
`LL_VK_SCENE_VERIFY=1` with `LL_VK_SCENE_GEO=1`: (a) per frame, for the main view, the union of the visible fragments' entries per pass type equals (as a multiset, matrices resolved to values, texture identity to the registry's current name) the entries the builder made for the same type (the builder is still run in verify, as for the shadows); count, vertex / index / offsets, flags, material values compared field by field; fallback draw infos equal; (b) texture slots: every entry's slots equal `packet_texture_slot(name the builder resolved)` at the time of the compare, stale names counted like the alpha registry; (c) first-frame pictures and a burst of screenshots against the old path (`FSDeferredPackets` default path) judged by eye and by difference image. Switch `LL_VK_SCENE_GEO=1`, off by default, FS setting later.

## 6. Stages (each a commit; London; old path intact and default)
- **G0:** worker timers for kind 3 (table build, matrices, record) and the main-thread zones as a baseline (no behaviour change).
- **G1:** viewer-side G entries in the fragment + verify compare against the builder (nothing sent to the worker yet). Gate: 0 mismatches over a long run.
- **G2:** worker table, commands and matrices from the visible list (`LL_VK_SCENE_GEO=1`); textures first by the per-frame resolve (names resolved for visible fragments only) to isolate the draw path. Gate: pictures identical.
- **G3:** textures by pins and events (the registry), keep-alive round robin; drops the 1,500 `prepareFast` calls.
- **G4:** `postSort` / pool loops stop carrying covered draw infos; measure.
- Not in S3: rigged / glTF / bump / fullbright / alpha mask / terrain / grass / tree draws (they keep their packets or the old path: bump and fullbright are the natural next types, the same layout), bridge groups and non-region matrices (S4), alpha (S5).

## 7. Decisions for Adam
1. **Visibility:** CPU group visibility (list of fragment ids, identical sets, occlusion kept) for S3, GPU frustum cull as a second mode only — instead of the plan's cull compute as the primary. Recommended; it changes the plan text.
2. **Gate:** replace "main thread -2 ms, worker draws about -4k" by: pictures identical, 0 verify mismatches, main thread `renderGeomDeferred` + `postSort` + builder zones down by at least 0.8 ms in London, worker table-build time (measured at G0) gone. The old gate predates the packets (section 2). Whether to continue under the corrected gate is the question; structure for S4-S5 is the other reason to (Adam decided that for S2-S5 on 2026-10-20).
