# F2.4+: the draw record (design, 2026-10-19; first slice not built yet)

Part of `PLAN-gpu-scene.md` (Foundation F), after F2.1-F2.3 (`F2-start.md`). Adam's rule: nothing GL-shaped (2026-10-10, 2026-10-19). Everything below was checked against the code on 2026-10-19 (branch native-vk, 0625177a).

## Where the draw stream really stands (read, not assumed)
- Every draw of the viewer goes through four producer functions: `LLVertexBuffer::drawRange/drawRangeFast/drawArrays/drawNoAttributes` -> `LLVkAsync::drawRangeElements/drawArrays` -> one `CMD_DRAW` (draw args + changed texture slots + changed loose uniforms, `writeDraw` in llvkasync.cpp). Vertex input is `LLVertexBuffer::setBuffer` -> `setArrayState` (CMD_ARRAY_RUN), program is `LLGLSLShader::bind` -> `shaderBind` (CMD_SHADER_BIND), render state is `CMD_STATE` when the block changed. No GL enum, name map or hook is left in the records (F1/F2.1-F2.2).
- What is still GL-shaped is the **semantics** of two record kinds, kept alive on the worker as a state machine: `shader_bind` = "unbind both buffers, switch the program, enable/disable attribute arrays by mask" and `vertex_input_apply` = "bind array buffer, set attribute pointers (offset as a pointer), bind element buffer" into `sVin` (a VAO emulation, `VaoAttrib`: mEnabled, mBuffer, mOffset ...). The draw then reads `sVin` + `Renderer::getProgram()` (set by the last shader bind) + the last `CMD_STATE`; `build_vertex_input` looks every buffer up by name in `sGL.mBuffers` (std::map).
- Measured stream (lean opstats run, crowd, 2026-10-19): 33.9k producer calls -> 14.4k records/frame, queue writing 0.89 ms/frame on the main thread (26 ns per call). Records per frame: draw 5.8k, arrayRun 4.4k, shaderBind 1.0k, texParamsId 0.9k, queryBegin/End 0.5k each, state 0.4k, uniformBlock 0.4k. Worker: draw 5.8 ms (1.0 us per draw), shadowPackets 3.1, rtScene 2.4, arrayRun 0.26.
- Consequence, stated plainly: the **record stream is not where the main thread's time goes** (0.9 ms of a 15 ms loop). Replacing records by a better record saves at most that plus about 0.3 ms on the worker. The per-draw cost on the main thread is the viewer code above the stream (LLGLSLShader::bind/uniform* with their value caches, LLTexUnit::bind, LLGLState objects, LLDrawPoolAlpha's own logic). That moves only when those front-end classes write straight into a context (F2.5/F2.6 below) and the work they do per call shrinks; it has to be measured per class first (see "Measure before F2.5"). F2.4 is the mechanism those steps stand on, not a speed-up by itself.

## F2.4 the draw record
**Producer (per producer thread, next to `Pend`): a `DrawContext` of values.** `program` (the `LLVk::Program*` of the last bind, null after unbind) and `binding` = `{ arrayBuffer, indexBuffer, attribute table for the locations the bound shader reads: size, type, normalized/integer, stride, offset }`. `LLGLSLShader::bind/unbind` set `program` and clear `binding`; `LLVertexBuffer::setBuffer` computes the binding **whole**, as a pure function of (this buffer, the bound shader's attribute mask), instead of the delta against `sLastMask`/`sGLRenderBuffer` that is replayed on the worker. `drawNoAttributes` draws with the empty binding.
**Binding in the record, not interned (slice 1).** A draw record carries the binding when it changed since the previous draw record of the same producer (a dirty flag in the producer's `DrawContext`; a sub-stream starts dirty and its last program/binding become the main producer's at the splice); otherwise it is absent. Ids with `CMD_BINDING_DEF` would need an ordering rule between the main stream and sub-stream buffers and a sweep for dead entries, and nothing reads an id yet; they come with the executor cache (F2.7) where a key is useful. The state block keeps its delta record (`CMD_STATE`, 0.4k/frame).
**The record.** `CMD_DRAW2 { kind/topology, start, end, count, index type, index offset, program, [vertex binding if changed], texture slot delta, loose uniform delta }` = today's `CMD_DRAW` plus the two things that used to be persistent worker state. A draw no longer depends on any earlier `shader_bind`/`array_run` record.
**Executor (worker), step 1 = minimal and exact:** at `CMD_DRAW2` set the program if it differs, expand the binding into `sVin` (enabled = present, array/element buffer, attributes) and run the existing `draw_elements/draw_arrays` unchanged. The Vulkan translation does not change in this step, so a picture difference can only come from the record side. Step 2 (own measurement) replaces `sVin` and the by-name map lookups by a cache `(binding id, program) -> VertexInput template` validated by the buffers' arena epoch, and a pipeline-key cache keyed by the state block.
**Switches (old path intact until F5):** `LL_VK_DRAWREC` = 0 old stream only (default until the gate is passed), 1 **verify** (old stream as today + `CMD_DRAW_CHECK` before every draw), 2 new records only. Same names in `rt-defer-start.ps1` (`RT_DRAWREC`).
**Verify mode (the gate).** The producer builds the binding and program in its `DrawContext` next to the old calls and writes `CMD_DRAW_CHECK {program, the producer's state block, the whole binding}` immediately before each old `CMD_DRAW`. When the worker reaches the draw it compares: (a) every old draw is preceded by exactly one check (draw counts equal, none lost or doubled), (b) program == `Renderer::getProgram()`, (c) the binding's present attributes == `sVin`'s enabled attributes with equal buffer, size, type, normalized/integer, stride, offset, and array/element buffer, (d) the producer's state block == the latest received block (the state record sequencing). First 30 mismatches are logged with program name and the field; counters per frame in the VkOps log. Gate: **0 mismatches over a long plaza run, a crowd run and a login-screen run** (login screen draws UI, HUD and sky programs the plaza does not). Only then mode 2.
**Why a global switch and not "one pass family" at a time.** A family-by-family executor switch means draws of two kinds share one worker (`sVin`, current program) and the producer's beliefs (`sLastMask`, `sGLRenderBuffer`, `sCurBoundShader`) must be handed back at every family boundary, the same work the sub-stream splice needed, for no gain: verify mode already covers every draw of every pass. The pass-by-pass moves are F3's (callers onto the context API), not the record's. If verify shows a bad family, mode 2 gets a program-name filter for bisecting, nothing more.
**Sub-streams:** each producer thread has its own `DrawContext`, so a sub-stream's draws are self-contained (the vertex-input beliefs no longer need a hand-back at the splice in mode 2).

## Then (each a commit with a gate, old path kept)
- **F2.5 uniforms by class on the producer.** The producer keeps, per program, the five class blocks (pass, draw, material, light, skin) the worker's `Program` already has; `uniform*()` writes into the class shadow (compare-before-write stays), the draw record carries the changed class ranges instead of per-uniform entries. Gate: bytes and ring copies per frame equal or lower, same pictures; main-thread `uniform*` ns per call before/after.
- **F2.6 texture units as a slot array of ids** (already the shape of `Pend::mTex`; drops `CMD_TEX_SLOTS` side records and the unit/class mapping on the worker: the program's sampler list names slots directly).
- **F2.7 executor caches** (step 2 above) and removal of `sVin`, `shader_bind`, `vertex_input_apply`, `CMD_SHADER_BIND`, `CMD_ARRAY_RUN`. This is where the worker's 1.0 us per draw is attacked.
- **Measure before F2.5:** main-thread cost per front-end entry point (`LLGLSLShader::bind`, `uniform1f/3fv/matrix4fv`, `LLTexUnit::bind`, `LLRender::blendFunc`, `LLGLState` ctor/dtor, `setBuffer`) by call count x ns, taken in one crowd run with CPU zones on a sampling basis, so F2.5/F2.6 target what costs, not what looks GL-like. This is a counter patch (no behaviour change), same style as the VkOps counters.

## Status 2026-10-19: slice 1 built and measured (LL_VK_DRAWREC 0 / 1 / 2)
Code: `LLVkAsync::drawBinding/drawBindingClear/drawProgram` (llvkasync.h), `DrawCtx` in the producer's `Pend`, `CMD_DRAW_CHECK` / `CMD_DRAW2` (llvkasync.cpp `writeDraw`), worker `draw_context_apply` / `draw_check` (llvkgl.cpp), `LLVertexBuffer::setBuffer` computes the whole binding when the record is on. Launchers: `<work>\run-viewer-drawrec-verify.bat`, `run-viewer-drawrec-new.bat`; scripted: `RT_DRAWREC=1|2` (+ `RT_NO_PHASES=1 RT_OPSTATS=1` for op stats without phases).
- **Verify (mode 1), London City crowd, 120 s: 37.5 million draws checked, 0 mismatches** in every category (program, state block, array/element buffer, attribute source, attribute fields, check without draw, draw without check).
- **Mode 2 found a bug the verify could not: the packet records** (`CMD_SHADOW_PACKETS`: deferred geometry, shadow alpha/skin, velocity) draw with `Renderer::getProgram()`, which the shader-bind record used to set. Without it the world's trees, buildings and furniture were missing (Adam saw it; I had judged the picture from one screenshot with no reference). Fix: mode 2 writes `CMD_PROGRAM_BIND` before a packet record when the producer's program differs from what the stream last set (`DrawCtx::mSent`). LESSON: when a record kind is removed, search the worker for EVERY reader of what it set (here `getProgram()` in six handlers), and compare screenshots against an old-path screenshot of the same spot before calling a picture right.
- **Mode 2 vs mode 0, same spot, same launcher style (opstats, no phases):** records/frame 13.8k -> 8.1k (-41%); producer calls/frame 32.4k -> 25.8k; main thread queue writing 0.77 -> 0.66 ms/frame; worker draw path (draw + arrayRun + shaderBind) 6.18 -> 6.01 ms/frame (draw ns 1075 -> 1125 with the binding expanded in the record, minus the 0.24 ms of the two removed record kinds); shadowPackets 2.65 ms in both. Draw counts 5.54k vs 5.33k per frame (the crowd differs by 3 avatars between the runs). Pictures: trees, buildings, couch, lamp, billboard all present in both. As expected from the design this is not a speed-up (-0.1 ms main, -0.2 ms worker); it is the base for F2.5-F2.7.
- Default is 2 from 8f8db7a8+1 (Adam: mode 2 is the way forward; `LL_VK_DRAWREC=0` is the old stream until F5). Not yet exercised in mode 2: snapshots, model/avatar previews, sub-stream and UI-substream modes (`FSUiSubstream` etc.), media textures. Run the REGRESSION-CHECKLIST items before flipping the default.
- Next: F2.5 (producer-side uniform classes) after the front-end per-entry-point counters ("Measure before F2.5" above); F2.7 removes `sVin`, `shader_bind`, `vertex_input_apply`, `CMD_SHADER_BIND`, `CMD_ARRAY_RUN` once mode 2 is the default.

## F2.5 step 1: where the main thread's front-end time goes (2026-10-19, counters, London City crowd, mode 2, lean opstats run)
Counters (`LLVkAsync::FrontLap`, every 16th call timed, only with `LL_VK_OPSTATS`; the VkOps "worker operations" line has a `FRONT END main thread:` part). Per frame:
| entry point | calls | ms | ns/call |
|---|---|---|---|
| `uniform*` (all setters but matrices) | 23,539 | 0.52 | 22 |
| `uniformMatrix*` | 3,521 | 0.14 | 39 |
| `syncMatrices` (5,848 calls, contains the matrix writes above) | 5,848 | 0.12 | 21 |
| `LLVertexBuffer::setBuffer` | 4,390 | 0.38 | 86 |
| `LLVertexBuffer::draw*` (writes the CMD_DRAW2) | 5,263 | 0.35 | 66 |
| `LLGLSLShader::bind` | 1,066 | 0.14 | 128 |
| `LLTexUnit::bind` | 893 | 0.11 | 121 |
| `LLGLState` ctor+dtor | 5,333 | 0.05 | 9 |
| `blendFunc`/`setSceneBlendType` | 3,057 | 0.04 | 12 |
Only 7,852 of the 23,539 uniform calls reach the stream (the producer's value cache filters 67%). Total of the listed entry points about 1.8 ms of a 15 ms loop: the classes' own work is not where most of the main thread goes (the rest is the pass code above them: culling, sorting, building lists, avatar and object update). What the numbers say to do inside F2.5: (a) `setBuffer` recomputes the whole binding (86 ns x 4.4k = 0.38 ms) on almost every draw: a cached binding per buffer and shader mask removes most of it; (b) the uniform path costs 22 ns for a call that is usually filtered: the filter is a hash map lookup (`mValue`) plus an initializer-list/mirror call chain, and a matrix write with `transpose` allocates a vector; a per-program shadow indexed by uniform replaces the map; (c) the 7.9k writes that do go out become class range writes resolved on the producer (no uniform index, no op dispatch on the worker).

## F2.5 done 2026-10-19: uniforms as class block range writes (LL_VK_UNIFORMREC 0 / 1 / 2, default 2)
- **What it is.** `LLGLSLShader` keeps a copy of its program's five class blocks (`mVkShadow`, copied from `LLVk::Program::shadowOf` when the program is made, so the shader-text initial values are in it) and `mVkUni` (class, byte offset, array size by the program's uniform index). `mirrorScalar/Vector/Matrix` resolve a write to bytes in that copy (`vkWriteFloats`, `vkWriteMatrix`: std140 column layout, the row-major transpose done in place, inline compare/copy), compare, and send only the changed range as `CMD_UNIFORM_RANGE {program, class, offset, size, bytes}` inside the draw's uniform batch; the worker does one `Program::writeRange` (memcmp, memcpy, class dirty). The per-shader hash map value cache (`mValue`, `uniformValueChanged`) and the per-uniform records (`uniformScalar/Vector/Matrix`) are bypassed in mode 2; samplers keep a per-sampler last unit instead of the map. Only the main thread (not a sub-stream) owns the copies (`LLVkAsync::mainOnlyProducer`); other producers use the old records (their writes are not in the copy: same limit as the old value cache, sub-stream modes are off by default).
- **Verify (mode 1)**: the old path runs as before and the producer's range writes go to a second copy of the blocks (`mShadowNew`); after each draw's uniform batch the worker compares the program's real blocks with it (the bindless slot bytes the worker writes itself left out). **Gate: 30.9M and 27.4M draw checks in two crowd runs (before and after the compare was made inline), 0 differences.** Log: `VkDrawRec` lines, "uniform blocks: checks N, draws with a difference N".
- **Measured** (London City crowd, same spot, opstats lean run; the first column is draw records with the old uniform path, the second is the default now): records/frame 8.1k -> 7.9k, producer calls/frame 25.8k -> 22.4k, queue writing 0.66 -> 0.63 ms/frame; **worker draw path 1126 -> 1012 ns per draw (6.0 -> 5.1 ms/frame)**; frame pacing 15.3 -> 14.5 ms (scene drift applies: one run each). Main thread front end: `uniform*` 0.52 -> 0.49 ms; matrices 0.14 -> 0.22 ms (39 -> 64 ns per call: it now compares instead of sending every matrix, but the compare and the resolve cost more than the old blind copy); net main thread about +0.05 ms. Picture: same as the old path (trees, buildings, couch, lamp, billboard, shadows).
- **Reading.** F2.5 is the foundation step (no per-uniform records, no uniform index or op dispatch on the worker, class ranges as the unit the scene tables will use), and it pays on the worker (-0.9 ms), not on the main thread. The main thread's front end, as measured, is small (1.8 ms) and `setBuffer` (0.36 ms) and `draw*` (0.35 ms) are the next cheapest to cut: a cached binding per buffer and shader mask (F2.7 prerequisite: the verify mode already compares the binding against the old state machine) and a leaner `writeDraw`. Not done: texture slots as an array of ids (F2.6), executor caches and deleting `sVin`/`shader_bind`/array run (F2.7).

## F2.4b: the setBuffer binding cache (2026-10-19) (a part of the F2.4 draw record that the F2.5 numbers pointed at; not F2.5, not F2.7)
`LLVertexBuffer` keeps the last binding it worked out (`VkBindCache`: vertex count, type mask, shader attribute mask, array and index buffer ids, the `DrawBinding`). The attribute pointers are a function of exactly those (`mOffsets` come from `calcOffsets(mTypeMask, nverts)` in `updateNumVerts`), so `setBuffer` reuses the binding (`LLVkAsync::drawBindingSet`) instead of running `setupVertexBuffer` and the conversion; modes 0/1 still compute the attribute pointers when their own old state needs them. **Gate: LL_VK_DRAWREC=1 + LL_VK_UNIFORMREC=1 verify, 27.4M draws, 0 mismatches in every category** (program, state, buffers, attribute source and fields, uniform blocks). Measured (crowd, default mode): `setBuffer` 86 -> 48-59 ns per call (0.36 -> 0.23-0.26 ms per frame); other entry points moved +-30% between the runs (machine and scene noise: matrices 64 -> 85 ns in the same runs), so read the ratio, not the absolute. Pictures: runs 2 and 3 identical to the baselines; **run 1 lacked the Megastore posters and the Soho billboard** (objects not loaded at the screenshot time, 100 s after login: the avatar crowd also differed; two further runs of the same build were complete). Not proven to be streaming; if a missing-geometry report shows up in mode 2, check this first (`LL_VK_DRAWREC=0` is the old stream).
