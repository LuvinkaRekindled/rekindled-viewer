# Family 3: the G-buffer fill and velocity (note started 2026-11-08, before any new shader)

Adam's go, 2026-11-08: "G-buffer fill" is the next family (after the alpha family; the lighting resolve's leftovers, softenLight 0.23 ms and the haze passes, come after or alongside). Rules in force: speed first, the picture stays (PLAN-shaders-rewrite.md sections 11, 15, 16), programs small and not 1:1 with the old ones, anything visibly different is shown to Adam first.

## 1. What the family is today (read in the code, RT off, crowd lap gz9: 0.59 ms opaque scene table draws + 0.07 terrain + 0.19 avatar velocity of a 6.4 ms GPU frame)

**What a fill shader does.** Almost nothing. The G-buffer shaders are 1.6 to 4.6 KB of GLSL:

| program family | fragment source | what it writes |
|---|---|---|
| legacy diffuse (the "Deferred Diffuse Pull" family, the bulk of prims) | diffuseF.glsl, 1.6 KB | albedo = vertex colour * diffuse map, spec = vertex alpha in all four channels, normal target = normalize(normal) + env (vertex alpha) + flag HAS_ATMOS |
| legacy material (normal / specular maps, alpha mask, emissive) | class3 materialF.glsl (the class1 file is a stub), about 10 KB with its blend branch | albedo rgb + emissive in alpha, specular rgb + glossiness, normal (map applied) + env intensity + flag; the blend branch is the old forward alpha path (dead in the Vulkan packet path: the alpha family replaced it) |
| glTF opaque and mask | pbropaqueF.glsl, 4.6 KB | albedo (linear), occlusion / roughness / metal, TBN normal (flipped for back faces) + flag HAS_PBR, emissive only if the emissive buffer is on |
| terrain, avatar, eyes, tree, bump, fullbright, emissive, impostor, HUD copies | terrainF 2.3 KB, avatarF 1.6 KB, bumpF 2.1 KB, fullbrightF 2.8 KB, pbrterrainF 14.7 KB | the same targets |
| velocity | avatarVelocity* / objectVelocityPull / motionVectors | motion vectors for DLSS (0.19 ms) |

Variants multiply them: alpha mask / no colour, skinned, indexed, HUD, impostor, 78 variants of the material fragment alone. Targets (pipeline.cpp `addDeferredAttachments`): albedo (the target's own first attachment), ORM / specular RGBA8, normal RGBA16 (RGB10A2 without HDR), emissive RGBA16F only with `RenderEnableEmissiveBuffer` (default off: glTF emissive then clamps at 1.0 in the 8 bit albedo). 16 to 20 bytes a pixel written, read once by the resolve.

**Where the time is NOT.** The research of 2026-11-08 (PLAN-shaders.md section 5) found the same for the cascade alpha casters: fragment shader work and texture fetches were noise; draws that do nothing (a draw command for every row, culled ones empty) cost 0.08 to 0.19 ms a pass; the PC sampler's warp share is not milliseconds. And the overshading count (PLAN-shaders-rewrite.md section 8): the opaque G-buffer shades about 3.2 fragments per screen pixel; the rigged crowd is vertex bound (234k triangles, 14k fragments in one type). So the shaders themselves are not where this family's milliseconds are; a native port of diffuseF / materialF / pbropaqueF would be the blur story again (same ms, expected, and worth doing only as the base for what follows: one small program per kind, specialization constants instead of 78 copies, own code).

## 2. Keep list (must not change; each needs a test spot)

1. Plaza ground shine and every reflection source: the albedo / spec / glossiness / env values written per pixel must stay bit-close (the resolve's shine comes from them). Test: plaza, night and day.
2. Legacy materials: emissive in the albedo alpha, glossiness from the normal map's alpha, env intensity = env * specular map alpha, vertex alpha doubling as the spec value of plain prims (the diffuse shader writes it into the spec target and the env slot). Test: a shiny prim and a normal-mapped prim.
3. Alpha mask edges (the 1/512 bias that stops acne at 8 bit alpha boundaries), glTF mask cutoff, back-face normal flip, mirror clip plane.
4. The flags in the normal target's w (HAS_ATMOS, HAS_PBR, SKIP_ATMOS, HDRI): the resolve, DLSS and the RT shaders read them.
5. Velocity: DLSS motion vectors for avatars, rigged objects and moving objects stay correct (hair and attachments were a glitch hunt before).
6. glTF emissive: stays as is (clamps at 1.0 with the emissive buffer off) unless Adam approves the HDR emissive field below.

## 3. Settings that steer the family

`RenderEnableEmissiveBuffer` (third target), `RenderHDREnabled` (normal format), `RenderDeferredSSAO`, classic mode (sets the material tweaks, not the fill), `FSTexAnimOnGPU` (texture animation in the vertex shaders), the draw packet path switches (live keys `native_*` do not touch the fill yet), mirrors (clip plane), impostor render.

## 4. Where the cost can go (candidates, each to be measured before any code; none is a decision)

1. **Measure the floor first.** Like the cascade casters: a live key that culls every row of the main G-buffer pass (zero sized draws) and one that clips every triangle after the vertex stage give the cost of the draws alone and the vertex part; what is left is the raster and pixel part. What the code says before any lap: the main pass commands are built on the CPU per listed fragment (`mRCmds` / `mRRuns` in llvkworker.cpp, the C4.5 visible set), so the culled objects are not in the list the way every row is in the cascade casters' resident cull; only draws the Hi-Z box test zeroes after the list is made would be empty ones. So the empty-draw lever of PLAN-shaders.md 5c is probably small here: the floor key tells, and the answer decides whether the compacted draws (append visible draws, `DrawIndirectCount`) apply to the main pass at all.
2. **Depth pre-pass experiment** (PLAN-shaders-rewrite.md section 8, option E): draw the opaque types depth only first, then the G-buffer at equal depth, and re-measure invocations (3.2 a pixel now) and ms. Cheap vertex work for the crowd is the risk (it doubles the vertex stage), so the pre-pass is for the static types; test per type.
3. **Fullbright and emissive-only surfaces straight to colour** (option C): skip the G-buffer write and the lighting read for them. Needs the resolve to leave those pixels alone (stencil or a flag test), so it pairs with the resolve work of family 1.
4. **Slim packing** (option A): normal RGB10A2 (4 bytes instead of 8), flags folded in: 12 to 16 bytes a pixel. Changes every reader (resolve, RT, DLSS inputs, SSR): measure the bandwidth gain with a throw-away format change first; expect tenths of a ms at most.
5. **One small native program per kind with specialization constants** (alpha mask, normal map, specular map, rigged, HUD) instead of the 78 variants: the compile and cache side gets simpler and the shader text becomes our own; the ms gain on its own is expected to be about zero (the blur lesson), so it is the base, not the prize.
6. **HDR emissive field** (R11G11B10F or RGB9E5): a visible improvement (glTF emissive above 1.0, glow that blooms) for Adam to approve; costs a little bandwidth when on.
7. **Visibility buffer** (option B): the largest rewrite for at best a few tenths of a ms; decided after the pre-pass experiment, not before.

## 5. First steps (proposed)

(a) the floor keys of candidate 1 in the main pass, one lap (needs a crowd spot or Adam's home: the plaza is not available; compare only inside a lap); (b) from the numbers, either the compacted main-pass draws or the depth pre-pass experiment; (c) the native fill programs as the base for the packing and emissive changes.

## 7. Results log

**7.1 The floor of the G-buffer pass (2026-11-08, lap gf1-phasesoff1, Adam's home, RT off, zone timers on, nine 18 s windows: key values 1 / 2 / 3 three times each).** The measuring key is `gfloor` in rt-debug.txt (llvkworker.cpp, `geo_draw`; 1 = normal, also when missing, 2 = every command of the table draws made empty, 3 = a zero scissor round the draws: the vertex stage runs, every triangle is thrown away before the rasteriser). `<work>\zones-by-window.py <lap>` averages the zones per key value. GPU frame 3.60 / 3.09 / 3.14 ms (the rest of the drop is the lighting passes and the lit surfaces that are gone from the picture, so only the G-buffer zones count here):

| zone (GPU ms) | normal | empty draws | clipped after vertex |
|---|---|---|---|
| pool: materials | 0.088 | 0.006 | 0.002 |
| pool: simple | 0.073 | 0.005 | 0.000 |
| pool: alpha mask | 0.009 | 0.000 | 0.000 |
| scene table type 10 rigged | 0.040 | 0.003 | 0.034 |
| scene table type 7 rigged | 0.039 | 0.003 | 0.026 |
| types 5, 11, 2 rigged | 0.011 / 0.010 / 0.010 | 0.001 / 0.001 / 0.000 | 0.009 / 0.009 / 0.008 |

Reading: (1) the draws themselves are free in the main pass (empty draws: 0.01 ms for everything), so the compacted-draw lever of the cascade casters does not apply here, as the code reading said. (2) The static opaque fill (pool materials + simple, 0.17 ms here) is all raster and pixel work: with every triangle clipped after the vertex stage it is 0.002 ms. The levers are on the pixel side: the overshading (depth pre-pass), the bytes written (packing), fullbright straight to colour. (3) The rigged types are the opposite: with every triangle clipped they keep about 80% of their time (type 10: 0.040 -> 0.034, type 7: 0.039 -> 0.026): the skinning vertex work is the cost, not the pixels, as the plaza census said. At this scene the whole fill is about 0.3 ms; the crowd spot has far more rigged work, so the rigged share there is the part to look at (needs Adam parked at the crowd). (4) Side effect seen in the same table: with the geometry gone the sky shaders run over the whole screen (haze 0.023 -> 0.16, clouds 0.018 -> 0.10), which confirms the late sky saves that cost in a normal frame.

**7.2 The most a depth pre-pass could win (2026-11-08, lap gf2-phasesoff1, Adam's home, zone timers on, `gfloor` 1 / 4 alternating, five and four 18 s windows).** Mode 4 draws every static (non rigged) table draw a second time against the depth the first one wrote (less or equal, no depth write), so the fragment shader of the second draw runs once for each visible pixel. Zones (GPU ms, normal -> normal plus the second draw): pool materials 0.108 -> 0.190 (the second draw costs 0.082), pool simple 0.087 -> 0.152 (0.065). The pass with no overshading costs 75% of the normal one: the overshading is worth at most 0.026 + 0.022 = about 0.05 ms here, before the pre-pass's own cost (vertex work and raster of the whole scene again, at least as much as that). **A depth pre-pass is dead for the static types at this scene** (net about zero or worse); the static fill is cheap because it is bound by the pixels that are really visible, not by hidden ones. Adam saw the glow rise while mode 4 was on: the second draw writes the same G-buffer targets again (the emissive lives in the albedo alpha), so the picture with the key on is not a valid picture; the key is a measuring tool only and is off by default. Not measured: the crowd spot, where the static overdraw may be higher (3.2 fragments a pixel was measured there).

**7.3 Fullbright straight to colour: already how it works (2026-11-09, read in the code).** Candidate 3 above was written from the plan's option C without checking the draw pools: `LLDrawPoolFullbright` (and its alpha mask and shiny forms) draws in `renderPostDeferred`, after the lighting resolve, with `fullbrightF.glsl` writing `frag_color` (the lit colour target) and no G-buffer write; its zone is "post pool: fullbright" (0.02 ms at Adam's home). So there is nothing left to move for fullbright surfaces, and nothing to read back in the resolve for them. What could still be looked at under the same idea is small: legacy materials with their emissive set to the full value (they go through the G-buffer, the emissive in the albedo alpha) and glTF surfaces with only an emissive texture; neither is a measured cost.

**7.4 Slim normal target: RGB10A2 instead of RGBA16 (2026-11-09, setting `FSGBufferSlimNormal`, default off, read when the targets are made; laps sn0 / sn1 / sn2 = off / on / off, Adam's home, RT off, zone timers on, 108 s of readings each).** The encoding needed no change: the octahedral normal and the environment intensity are 0..1 floats (10 bits each is a normal step of about 0.004, a quarter of a degree) and the flag takes the values 0, 0.34, 0.67, 1.0, exactly the four values of two bits (the non-HDR mode already ran this format). Zones (GPU ms, off / on / off again): pool materials 0.098 / 0.081 / 0.100, pool simple 0.080 / 0.070 / 0.080, atmospherics (the resolve) 0.210 / 0.210 / 0.210; the sum of the listed passes 3.552 / 3.514 / 3.587. So the slim target takes about 0.03 ms off the fill (the second off lap agrees with the first) and the resolve's read is below the timer's 0.01 ms resolution; about 0.04 to 0.07 ms off the frame at this scene, 1 to 2 percent. Picture: the screenshots of the three laps (still camera, the avatar moves) differ from each other by less when old is compared with slim (mean 1.6) than when old is compared with old (mean 2.1), and nothing shows in the picture; the thing to look at by eye is a very polished surface (a mirror floor, chrome) where a quarter degree normal step could band a highlight, and the plaza ground shine. Not measured: the crowd spot (more fill, so likely a larger gain).

**7.5 The native G-buffer programs had never drawn, until the output-count check was skipped for them (2026-11-09 evening, laps gbr1 / gbr2 / gbr3, plaza, RT off, zone timers on).** The family of commit `dd0e405c53` (glTF opaque and mask, plain prims, legacy materials; and the legacy terrain written on the same evening) compiled and was created, but `nativeOverride` (llvknative.cpp) refused every stand-in whose number of output names differs from the old program's: the viewer's programs declare ONE array (`out vec4 frag_data[4]`, one name), the native ones one variable a target (frag_albedo, frag_spec, frag_normal, frag_emissive), so no G-buffer stand-in ever counted the same and the old programs kept drawing. Found when the native terrain compiled and showed no draw counts (the log line `native program '<name>': N draws so far` is the check: it never appeared for them in any lap). The commit message's "all programs compile and draw", the picture compare (it was old against old) and the zones of that evening were therefore about the old programs. Fix: the check no longer applies to the `gbuffer` family (it exists for the sun program with the ray traced blocker output). Since then every program of the family draws (draw counts in gbr1: diffuse, diffuse mask, diffuse skin, materials 0..14 static and skin, glTF opaque skin, terrain), no error, 0 scratch failures, 0 unknown handles, 0 bad ranges. Picture (lap gbr2, native_gbuffer 0 / 1 in turns, three pairs, six grabs each, still camera, medians): old against new mean error 0.98 (more than 8 levels on 2.7 % of the pixels), old against old halves 1.26 (3.3 %), new against new halves 1.56 (3.3 %): no difference above the noise; the difference map is black over the static scenery (paving, buildings, trees) and bright only on avatars, name tags, the video screen and the animated glow. Zones (lap gbr3, six windows of 12 s, five readings each): sum of the listed passes 4.878 ms old, 4.824 new (inside the window noise of 0.1), pool terrain 0.066 / 0.062, pool simple 0.152 / 0.154: as the floor measurements of 7.1 said, the G-buffer fill is not where this scene spends its time, so the family is native for completeness and looks, not for speed. Terrain legacy (terrain.vert / terrain.frag: only the detail layers with a weight above 1/1024 are fetched, the ramp coordinates are worked out in the fragment program, 10 interpolated floats instead of 14) is in this lap; the plaza's terrain is a small share of its pixels, so no gain can show here. **7.6 The native legacy terrain drew a flat colour: found by Adam's eye, fixed (2026-11-09 night).** The terrain program of 7.5 declared `texture_matrix0` as a uniform. In the pull path the old program has no such uniform: its prologue builds it from the row (`texture_matrix0 = row.pad.x != 0 ? texmats[row.pad.x] : mat4(1.0)`, with the texture animation made against the clock). Nothing filled the native uniform, it stayed zero, every detail coordinate was (0, 0) and the lawn sampled one texel: flat green. The plaza laps of 7.5 did not show it because the plaza's ground is not legacy terrain (the diff map was black there for lack of any terrain pixels). Fix: `terrain.vert` takes the matrix from the row (`row_texture_matrix`, like every other native table program); the uniform is gone from `alpha_pass.inc`. Checked at London City, Soho and Regent's Park (a lawn of legacy terrain), still camera, native_gbuffer 0 / 1 in three pairs of two grabs: old against new medians mean error 0.10, no pixel off by more than 8 levels (old half against old half 0.12). Lesson: for a native stand-in of a pull program, list the uniforms the OLD PULL program really has (the pull prologue in llshadermgr.cpp removes or replaces the matrices), and test the family in a scene that uses it.

**7.7 The Linden trees of the G-buffer pass are native and go through the packet path (2026-11-10, Cortina (22,108), two Linden trees and bushes in view, live session, hot reload).** `LLDrawPoolTree::renderDeferred` drew every face with its own bind, region matrix and draw (the only G-buffer pool left with that loop; the cascades' trees were already packet records). Now, when `gTreePullReady`, it sends all the pool's faces as one record (`LLFacePool::pushWholeBufferFacesPull`: the buffer's own index count from 0 under the region's render matrix, since a tree face's index range is not the face's) to a `Deferred Tree Pull Shader` made from treeV / treeF with LL_VERTEX_PULL, like the terrain's; `LL_VK_TREE_PULL=0` keeps the old loop (read at start). Native `tree.vert` / `tree.frag` stand in for it (family gbuffer): the constant white vertex colour and its varying are gone, the texture matrix is the row's (7.6), the alpha cutoff is the existing `minimum_alpha` of `LLLooseMaterial` (a first version declared it twice and did not compile: the log line `compile failed for tree.vert` is how it showed). Draw counter: 2001 draws after the fix. Picture (native_gbuffer 0 / 1 in turns, the pairs taken while the camera was still): old against new on the trunk crop mean 0.27 / 0.29 against 0.18 for two old frames, on the bush crop 0.16 / 0.10, no pixel off by more than 8 levels there. Cost: not measurable with two trees; the saving is commands and CPU (about 4 queue calls a face at 52 ns, so a forest of 300 faces is about 0.06 ms of the main thread): the point is that no G-buffer pool draws face by face any more, not speed. Still old: PBR terrain, bump and emboss, impostor, the system avatar.
**7.8 Bump and emboss are native (2026-11-10, Ibiza club "Freebies and bargains", live session; hot reload does not read new manifest lines, a restart does).** `gbuffer.vert` gets two defines: `GB_BUMP` (tangent, its sign and the bump image's slot from `row.mapSlots`) and `GB_EMBOSS` (the second coordinate set through the row's texture matrix); `gbuffer_bump.frag` is `bumpF.glsl` for "Deferred Bump Pull Shader" and its skin variant (diffuse times vertex colour after the row's cutoff, the bump image read as a tangent space normal, the vertex alpha as specular value and environment intensity, flag HAS_ATMOS; the tangent frame is two varyings and a flat sign where the old pass sent three vec3 rows), `emboss.frag` is `objects/bumpF.glsl` for "Deferred Emboss Pull Shader" and its skin variant (the bump image's alpha read twice, `max(a0 + (1 - a1) - 0.5, 0)`); four manifest lines, family gbuffer. Both compiled at the first start and draw: draw counter 8001 draws each after 30 s in the club. Picture (`native_gbuffer` 0 / 1 in turns, three pairs, desktop grabs, the room is lively): on the pink bump mapped wall crop old against old 0.81, new against new 0.72, old against new 0.75 (mean error), on the dark floor 0.03 / 0.02 / 0.04, on the animated pool edge 10.6 / 11.3 / 9.1: the difference between old and new is inside the difference between two old frames. Cost: not measured (bump mapped prims are rare; the point is that the G-buffer family has no old program left for them). Still old: PBR terrain, impostor, the system avatar.
**7.9 The avatar impostors are native and one record a pass (2026-11-10, London City, live session and unmanned smoke laps).** `LLVOAvatar::renderImpostor` drew each impostor as an immediate mode quad (6 vertices, three texture binds) with "Deferred Impostor Shader" (impostorV / impostorF.glsl). Now `LLDrawPoolAvatar::renderAvatars` (pass 0) collects one `LLVkBridge::ImpostorQuadRow` per avatar (`LLVOAvatar::fillImpostorQuad`: centre, left and up half axes of the camera facing quad, the GL names of the target's diffuse, specular and normal images) and `endDeferredImpostor` sends them as one **kind 41** record (`on_impostor_quads` in llvkworker.cpp: the names become the frame's bindless slots, the rows go to a scratch buffer whose address is the program's `ll_impostor_table`, one indirect draw of 6 vertices a row, the row chosen by the instance; the pattern of kind 33, the light volumes). `impostor.vert` builds the corners (the order of the old quad), `impostor.frag` copies the three images to the G-buffer's targets (diffuse alpha against `minimum_alpha`, the normal image's rgb with the flag 0.34). The old program has no table, so **only the native stand-in draws**: with `native_gbuffer=0` (or a failed compile) impostors are not drawn and the log says so once ("avatar impostors are not drawn: the program ... has no ll_impostor_table"). The old immediate path is gone but for the debug outline (RENDER_DEBUG_IMPOSTORS). **Lessons:** a uniform block must declare the same members in both stages (the first version did not link); a buffer reference variable cannot be `const` in GLSL (the second did not compile: the log line `compile failed for impostor.vert` and the worker's warning showed it; impostors vanished, only tags and crosshairs stayed); the loader retries a failed program only when it is drawn again. **Cost:** before the change the quads cost the main thread 24 to 25 a frame at 0.40 to 0.42 us each, 10 us a frame (0.010 ms); the record replaces them by one record and 25 rows, not measured again, the saving cannot be more than that. Checked by the draw counter (the program draws) and by Adam's eye ("works"); a picture A/B was not made (the old version cannot be drawn any more and a camera angle is not repeatable). Still old: the system avatar, PBR terrain.
