## What S2 is (from the plan, narrowed)
"GPU-driven shadow casters. Cull + indirect for the sun cascades (non-ray modes) and for the ray scene's caster set; removes renderShadow and the per-frame noting. Gate: shadow pictures identical, main thread -3 ms, scene call -1.5 ms."
Suggested order, each its own commit, London only, builds with `run_in_background`:
1. **Entries on the GPU, by delta.** The worker's fragment table (id -> entries) becomes a device-local `Entries[]` range per fragment in the arena (stable addresses), plus a small per-region / per-matrix `Instances[]` table (static groups share the region matrix; bridge groups have their own pointers; matrices change on region shift). RETAIN writes the range, RELEASE frees it. The main thread then sends per frame only "the fragments in view" cheaply, or nothing if step 2 culls on the GPU.
2. **Cull compute for the cascades:** a frustum test per fragment (needs a bounding sphere / box per fragment: the group's bounds, `LLSpatialGroup::mBounds`, sent with RETAIN) and per entry, appending survivors to an indirect argument buffer; one `vkCmdDrawIndexedIndirectCount` per cascade through the existing pull shader (`shadowPullV.glsl`, the `ll_packet_table` layout). **Decision to make first:** does the main thread still pick the visible groups (cheap list of fragment ids, as now but without per-entry work) or does the GPU test all fragments? The first is the small step; the second removes `postSort` work for shadow views (phase 4 of `PLAN-retained-records.md`).
3. **Ray scene feed:** in ray shadow mode (Adam's default, `FSVkRayTracing`) the cascades are note-only (`rt_skip`) and the fragments are skipped today; the 7.8k `noteCaster` calls per frame (1.4 ms per scene call) should come from the retained entries instead (the BLAS cache is already persistent and incremental).
4. Verify mode for the GPU path: compare the culled entry set against the builder's list (read back in verify only), then pictures against the old path and `FS_CPU_ZONES=1` zones.
